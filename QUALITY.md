# Quality Record — every issue we've hit, and what stops it happening again

Every problem found in this project is recorded here with its fix and the **guard** that prevents it from coming back. A guard is either an automatic check (the build or CI fails) or a rule in [PROJECT_PLAN.md](PROJECT_PLAN.md) that every topic is checked against before it ships (workflow step "Check against the Quality Record").

When a new issue is found: fix it, add a row here, and add or strengthen a guard. Prefer an automatic check over a written rule whenever one is possible.

## Automatic checks (run on every push; a failure blocks the deploy)

| Check | Where | Catches |
|---|---|---|
| Flow check: no live topic has an unreleased topic before it in its domain | `site/src/lib/live.ts` (build) | Reels appearing "out of nowhere" |
| Concept ledger: everything a live topic `uses` was introduced by an earlier live topic or is `declared` | `site/src/lib/live.ts` (build) | Concepts used before they are taught |
| Every live topic has a `bridge` and a `handoff`, and its kind (full / refresher) matches the syllabus | `site/src/lib/live.ts` (build) | Abrupt starts and endings |
| Every topic title, and every on-site reel named in a Prerequisites panel, exists in the syllabus | `site/src/lib/live.ts`, `site/src/components/Resource.astro` (build) | Links to topics that don't exist |
| On-site reels in Prerequisites are labelled from the syllabus order ("Before this", "Goes deeper later", other track) | `site/src/components/Resource.astro` (build) | A panel contradicting the course order |
| Coverage map: every finished topic (live or held) has a `coverage.json` whose clauses cover its whole syllabus line word for word, plus at least two primary sources' contents, an independent blind expert list and a gap review with nothing open; every item points to a real reel step, Deep dive heading, or another topic whose syllabus line is quoted to show it covers it | `site/src/lib/coverage.ts` (build) | Topics that are correct but incomplete; "covered elsewhere" claims that aren't true |
| Topic files: narration has one entry per reel step with an `answer` exactly on predict steps; narration lines have no digits, symbols or code-style names; every number in the reel's on-screen text is computed or asserted in `examples.py` (step durations, years and wrong answer options excepted) | `site/src/lib/topic-checks.ts` (build) | Narration out of step with the reel, unspeakable lines, numbers on screen that nothing verified |
| Outside links load (404/410 or a dead domain fails) and Resource titles match the page; bot-blocked pages and title mismatches are listed for a human | `npm run check:links` (routine, before shipping) and `.github/workflows/links.yml` (weekly) | Dead links, wrong videos, mislabelled resources |
| Every topic's code examples run and their asserted outputs hold | `npm run test:examples` (`examples.py` per topic) | Wrong or outdated code on screen |
| Reel smoke test at 1440 × 900 and iPhone size: no page or console errors, no sideways scroll, every step renders a non-empty visual, no text in a drawing clipped, overlapping or running into other text, or under 9 px tall, predict steps answerable, pause/replay/restart controls exist and pause freezes the clock, on phone a real touch swipe left/right moves exactly one step on every step and a vertical swipe never changes the step, every panel opens with content on first and second open, outside links open in a new tab | `site/tests/reels.mjs` | Broken reels, empty panels, missing controls, layout overflow |
| Markdown relative links and anchors resolve | `scripts/check-docs.mjs` | Broken links in the plan and syllabi |
| Narration exists for every live reel, matches its current script, both formats present, every line word-perfect, loudness, peak and pace in range | `npm run test:narration` (`site/tests/narration.mjs`) | Missing, stale or badly mastered narration |
| The deploy also runs when only `syllabus/` changes | `.github/workflows/deploy.yml` | Site out of date with the syllabus |

## Before shipping any topic

Go through this list (it summarises the rows above):

1. Every topic before it in its domain is live; its `introduces` / `uses` ledger is filled in; it has a bridge and a handoff.
2. Every claim checked against primary sources; behaviour of real systems verified by running them; current docs quoted.
3. Every code example in `examples.py`, executed.
4. The coverage map is complete (syllabus line, sources, blind expert list), every gap from the gap hunt filled, and the build's coverage check passes.
5. Every resource link and its metadata verified.
6. Screens checked at desktop and phone size: nothing clipped, overlapping, too small or hidden behind controls; swipes work on a real phone.
7. Narration generated with `narration/narrate.sh` and listened to end to end.
8. `npm run build`, `npm run test:examples`, `npm run test:narration`, `npm run test:reels` and `npm run check:links` pass (links it reports for a human are opened by hand); any failure is fixed at its cause, never skipped or loosened.
9. No feature described before it exists.
