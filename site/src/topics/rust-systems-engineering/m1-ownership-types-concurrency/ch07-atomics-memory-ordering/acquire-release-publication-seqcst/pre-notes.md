- **Happens-before**: the relation the memory model uses to say one thread's operation is guaranteed visible to another's. *Where you meet it:* the edge a release/acquire pair creates, and the one Relaxed never creates.
- **Release**: an ordering for a store that carries every earlier write on its thread along with it, to any matching acquire (or stronger) load. *Where you meet it:* the write side of the fixed publication pattern.
- **Acquire**: an ordering for a load that, once it observes a matching release (or stronger) store, orders every later operation on its own thread after that store. *Where you meet it:* the read side of the fixed publication pattern.
- **SeqCst**: the strongest ordering; every SeqCst operation, on every thread, falls into one single order every thread agrees on. *Where you meet it:* the one store-load litmus test release/acquire can't close.
- **Dekker's algorithm / store-buffering**: a classic shape where two threads each store to their own flag, then load the other's — the canonical test of whether an ordering gives a single global order. *Where you meet it:* the predict step proving release/acquire still isn't enough there.
- **Fence**: a standalone ordering constraint not attached to any one atomic operation. *Where you meet it:* a spinlock whose compare-exchange loop stays relaxed while a separate fence does the acquire half.
- **`loom`**: the model checker from the previous topic, used again here — and, in one case this topic, deliberately not used, because its own tests document a known gap for the SeqCst store-buffering shape. *Where you meet it:* every claim that is loom-checked says so, and the one that isn't says why.
- **x86-TSO**: the strong default memory-ordering guarantee x86-64 hardware gives, strong enough to hide some ordering bugs ARM's weaker default would expose. *Where you meet it:* the recap's closing warning against trusting "it worked when I tested it."
