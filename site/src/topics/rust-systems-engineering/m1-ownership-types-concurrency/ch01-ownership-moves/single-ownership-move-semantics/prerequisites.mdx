This is the first topic of Rust Systems Engineering. It assumes you have read *The Rust Programming Language* through chapter 10 and can compile and run a Rust file; everything about ownership is rebuilt from the memory level up, but the syntax is not taught. If one of the four items below is shaky, a few minutes with the matching resource is enough to follow every step.

<section class="prereq" data-section="compile">

### <span class="n">01</span> Compile and run Rust

`rustc` and `cargo`, and the 2024 edition. Every example in this topic is a single file you can compile with `rustc --edition 2024 main.rs` and run.

<p class="check"><b>Check yourself:</b> can you compile a single file with <code>rustc --edition 2024 main.rs</code> and run the result?</p>

  <Resource kind="reading" title="Hello, World!" href="https://doc.rust-lang.org/book/ch01-02-hello-world.html" by="Klabnik, Nichols and Krycho, The Rust Programming Language">Writing, compiling and running a first program with rustc.</Resource>
</ul>

<section class="prereq" data-section="stack-heap">

### <span class="n">02</span> The stack, the heap and pointers

What lives in a stack frame, what a heap allocation is, and what a pointer is. A `String` is a small fixed-size header on the stack that points at its text on the heap; the whole topic is about that split.

<p class="check"><b>Check yourself:</b> where do the characters of a <code>String</code> live, and where does the <code>String</code> itself live when it's a local? (Answer: the characters on the heap; the 24-byte header in the local's stack frame.)</p>

<ul class="resources">
  <Resource kind="reading" title="What is Ownership?" href="https://doc.rust-lang.org/book/ch04-01-what-is-ownership.html" by="Klabnik, Nichols and Krycho, The Rust Programming Language">Read "The Stack and the Heap", then the ownership rules and the move example.</Resource>
</ul>

</section>

<section class="prereq" data-section="borrowing">

### <span class="n">03</span> References, borrowing and slices

`&` and `&mut`, and how `&[u8]` and `&str` borrow part of something else. You should know that a shared reference lets you read and that a mutable reference lets you change a value, one at a time.

<p class="check"><b>Check yourself:</b> why can you still use <code>s</code> after <code>let r = &amp;s;</code>? (Answer: a reference borrows the value without taking ownership, so <code>s</code> is still its owner.)</p>

<ul class="resources">
  <Resource kind="reading" title="References and Borrowing" href="https://doc.rust-lang.org/book/ch04-02-references-and-borrowing.html" by="Klabnik, Nichols and Krycho, The Rust Programming Language">Shared and mutable references, and why the compiler limits them.</Resource>
  <Resource kind="reading" title="The Slice Type" href="https://doc.rust-lang.org/book/ch04-03-slices.html" by="Klabnik, Nichols and Krycho, The Rust Programming Language">String slices and array slices, the borrowed views the reel uses.</Resource>
</ul>

</section>

<section class="prereq" data-section="traits">

### <span class="n">04</span> Structs, traits and derive

`struct`, `impl`, `#[derive(...)]` and trait bounds. The reel talks about `Copy`, `Clone` and `Drop` as traits, and about types that implement them.

<p class="check"><b>Check yourself:</b> what does <code>fn f&lt;T: Clone&gt;(x: &amp;T) -&gt; T {'{'} x.clone() {'}'}</code> require of <code>T</code>? (Answer: that <code>T</code> implements <code>Clone</code>; the caller picks the type, and the bound lets the function call <code>clone</code>.)</p>
