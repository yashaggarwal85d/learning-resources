## Learning outcomes ("After this topic you can")

1. **Write down the exact order every destructor runs** in a given scope, nested struct, tuple, array, pattern and statement: `Drop::drop` first, then the fields in declaration order; locals in reverse declaration order; temporaries at the end of their statement (a `match` scrutinee's to the end of the whole statement, a `let x = &temp()` extended to the block); and under Rust 2024, `if let` scrutinee temporaries before `else` and tail-expression temporaries before the block's locals.
2. **Write a RAII wrapper for an OS resource** (`SpillFile`: a temporary file closed and unlinked in `Drop`) that releases exactly once, and explain *why* it cannot release twice: one owner, moves deinitialize the source, `Copy` is forbidden on a type with a destructor (E0184), and no one can call `Drop::drop` by hand (E0040).
3. **Explain why `mem::forget` is safe**, list every way a destructor is skipped (`forget`, `ManuallyDrop`, `Box::leak`, an `Rc` cycle, `process::exit`/`abort`, `panic = "abort"`), measure a leak with the chapter's counting allocator, and identify an API whose soundness wrongly depends on `Drop` running (the 2015 `thread::scoped` `JoinGuard`) against one that does not (`thread::scope`, which joins inside a function call).
4. **Spot the 2021 → 2024 migration hazards** around lock guards and other temporaries: why the Edition Guide's `if let` + `RwLock` function deadlocks under 2021 and runs under 2024, why `cargo fix --edition` keeps the deadlock (its `match` rewrite preserves the 2021 order), and why `tail_expr_drop_order` only warns.
