This topic follows "Single ownership and move semantics": you should know that every value has one owner, that a move deinitializes its source, and how to read a borrow-checker error. <section class="prereq" data-section="single-ownership">

### <span class="n">01</span> Single ownership and move semantics

One owner per value; a move copies the handle (the 24-byte header of a `Vec` or `String`) and deinitializes the source; `Copy` against `Clone`; reading E0382. This topic asks when the one owner's destructor runs.

<p class="check"><b>Check yourself:</b> after <code>let t = s;</code>, does <code>s</code> still drop anything at the end of the block? (Answer: no. The place <code>s</code> is deinitialized, so only <code>t</code> owns the value and drops it.)</p>

### <span class="n">02</span> Scopes and blocks

A block `{ ... }` is a scope; a function body is one; a `let` lives to the end of its block. The closing brace is where this topic's destructors run.

<p class="check"><b>Check yourself:</b> in <code>let a = T; let b = T;</code>, which is dropped first at the closing brace? (Answer: <code>b</code>, the reverse of declaration order. The reel proves it.)</p>

### <span class="n">03</span> Structs, traits and <code>impl Drop</code>

`struct`, `impl` and traits as in the Book through chapter 10. The `Drop` trait is a little past that baseline, so the reel builds it up from nothing: it is a trait with one method, `drop(&mut self)`, that the compiler calls when the value dies. The Book's chapter 15.3 is optional reading.

<p class="check"><b>Check yourself:</b> what does <code>impl Drop for T {'{'} fn drop(&amp;mut self) {'{'} … {'}'} {'}'}</code> let you run, and when? (Answer: your own cleanup code, automatically, when a value of type <code>T</code> goes out of scope or is dropped.)</p>

### <span class="n">04</span> <code>Result</code> and <code>?</code>

<code>SpillFile::create</code> returns <code>io::Result&lt;SpillFile&gt;</code> and the examples use <code>?</code> to pass an error up.

<p class="check"><b>Check yourself:</b> what does <code>?</code> do on an <code>Err</code>? (Answer: it returns that error from the enclosing function at once; on an <code>Ok</code> it unwraps the value.)</p>
