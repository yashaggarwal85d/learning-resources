<section class="prereq" data-section="chapter-so-far">

### <span class="n">01</span> The chapter so far

One owner per value; a move copies the handle and leaves the source moved-from (E0382); signatures are ownership contracts (`T` takes, `&T` borrows, `&mut T` borrows exclusively); a guard does its job in `Drop`; `Option::take` moves a value out of a `&mut`; and the guard `PooledBuf` holds the pool by exclusive borrow, so one guard exists at a time. This topic asks what to do when three stages need buffers at once.

<p class="check"><b>Check yourself:</b> who owns a value after <code>let b = a;</code> for a type that is not <code>Copy</code>? (Answer: <code>b</code>. The place <code>a</code> is moved-from, so using it is E0382.)</p>

### <span class="n">02</span> The running example in five signatures

The whole chapter uses one byte pipeline. Its parts, each in one line: <code>Pool::get(&amp;mut self) -&gt; Buf</code> hands out a buffer (the only place one is allocated), <code>Pool::put(&amp;mut self, buf: Buf)</code> takes it back, <code>fill(&amp;mut Buf, &amp;[u8])</code> writes into it, <code>inspect(&amp;Buf) -&gt; Header</code> reads a small <code>Copy</code> summary out of it, and <code>consume(Buf) -&gt; Buf</code> takes it, does its work and hands it back.

<p class="check"><b>Check yourself:</b> which of these takes ownership, and which only borrows? (Answer: <code>put</code> and <code>consume</code> take the <code>Buf</code>; <code>fill</code> borrows it exclusively and <code>inspect</code> borrows it shared.)</p>

<section class="prereq" data-section="borrowing-rule">

### <span class="n">03</span> The Book's borrowing rule

At any given time you can have either one mutable reference or any number of immutable references. This topic uses the rule only as the Book states it, as an ownership statement: two stages both wanting the pool's exclusive borrow is E0499. The model behind the rule (and why "mutable" there really means exclusive) is the next chapter.

<p class="check"><b>Check yourself:</b> why can't two <code>&amp;mut Pool</code> exist at once? (Answer: each would be allowed to change the pool while the other relies on it; the compiler refuses the second as E0499.)</p>

### <span class="n">04</span> Threads, channels, locks and lambdas as general ideas

From whatever language you came from: an OS thread you start and join, a FIFO queue between threads, a mutex around shared data, and a lambda that captures variables from its surroundings. Rust's <code>thread::spawn</code>, <code>mpsc</code>, <code>Mutex</code> and <code>|| …</code> are the same ideas, shown and glossed on the spot in the reel.

<p class="check"><b>Check yourself:</b> in a producer/consumer queue, who owns an item after it is enqueued? (Answer: the queue, and then the consumer that dequeues it; the producer must not use it again. That is exactly what a Rust send enforces.)</p>
