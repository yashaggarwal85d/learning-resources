## Storyboard (8 steps, 3 predict/reveal pairs)

1. **StructuredPredict** — Three real events each carry a real, structured `attempt` field (1, 2, 3) alongside their own differently-worded, rendered message. Does summing the structured field directly give the real, correct total? Options: no, a structured field is still just text underneath; yes, genuinely, it is a typed value, summed directly (correct); only if every message is worded identically.
2. **StructuredReveal** — Measured: summing the real, structured `attempt` field across all three real events gives exactly six, the real, correct total, regardless of how differently each event's own message happens to be worded. No separate takeaway here (this is the reel's own "from" step for the phone swipe test; its takeaway moves to step 7, the connecting step, below).
3. **FormattedPredict** — The identical total is attempted again, this time recovered only from each event's own rendered, formatted message, by pulling out the first run of digits found in it. Does that give the identical, correct total too? Options: yes, the numbers are right there in the text; no, genuinely, one real message spells its own number out instead of using a digit (correct); only if the messages are parsed in the wrong order.
4. **FormattedReveal** — Measured: the identical total, recovered only from each event's own rendered message, genuinely comes out to three, not six, since one real message ("third attempt now running") spells its own number out as a word rather than a digit, and the real extractor silently counts it as zero. Takeaway: a formatted sentence's own text is not a reliable source for a value a structured field already holds exactly.
5. **TraceContextPredict** — A real W3C Trace Context `traceparent` header is built from a real trace id, a real span id, and a real sampled flag, then parsed back. Does it round-trip exactly? Does a real, malformed header get rejected instead of guessed at? Options: it round-trips, but a malformed header is still accepted somehow; neither round-trips nor rejects correctly; it round-trips exactly, and the malformed header is genuinely rejected (correct).
6. **TraceContextReveal** — Measured: the real, formatted `traceparent` header, parsed back, genuinely recovers the identical trace id, span id, and sampled flag it was built from, and a real, malformed header is genuinely rejected rather than silently guessed at. Takeaway: a structured, specified format survives being handed to a completely different, independent parser; a sentence meant for a human does not carry that same guarantee.
7. **DocsReveal** — The W3C Trace Context specification and the `tracing` crate's own documentation state this directly, in their own words: a trace id and a parent id are real, specific byte values joined into one real, specified format; a span or event's own fields are key-value data, not unstructured text. Does this topic's own three measured comparisons model exactly the rule both sources describe? Takeaway (moved here from step 2): a structured field survives being queried, counted, and parsed by a completely different program later; a sentence written for a human to read was never built to survive that at all.
8. **Recap** — A structured field sums exactly, every time, no matter how its own event is worded; a formatted sentence can silently lose the identical value the moment it is phrased differently; and a real, specified format like `traceparent` survives being built by one program and parsed by a completely different one, exactly.
