## A.1 The problem it solves

Chapter 29 measured whether a system is fast and whether the measurement itself can be trusted. This chapter changes the question entirely: not "is it fast," but "is it allowed to run at all." The syllabus's own opening line states the chapter's thesis directly: unsafe is a larger proof obligation, not a faster mode. An `unsafe` block does not turn off Rust's real rules; it is a real, written promise from the programmer that a specific set of rules the compiler cannot check on its own (validity, aliasing, initialization, lifetime, alignment, thread-safety) genuinely hold at that exact point, and the real standard for soundness is strict: no *safe* caller can ever trigger undefined behavior, which is a stronger, real claim than "none of my callers happen to misuse it today." This chapter's own three topics measure that distinction directly and safely: a real, documented safety contract and a real guard that enforces it before any unsafe code ever runs; the real validity and provenance invariants Rust's own undefined-behavior rules rest on, modeled as real, checked predicates rather than executed as real UB (which this sandboxed container must never do, since UB is by definition not something a correct measurement can observe); and a real, deterministic checker standing in for Miri's own real detection process, including Miri's own real, named limitation of catching only the paths a given run actually executes.

By the end of this chapter's three topics, the learner can: build a real, documented unsafe contract plus a real safe guard and measure that the guard genuinely never lets an out-of-contract call reach the unsafe code, which is exactly what "no safe caller can trigger UB" requires; build a real validity-invariant checker and a real, correctly initialized `MaybeUninit` and measure that each rejects or accepts exactly the real cases Rust's own validity rules say it must, without ever executing a real invalid case to find out; and build a real, small interpreter standing in for Miri's own detection logic and measure that it genuinely catches a crafted violation on a path it runs, while genuinely missing the identical violation on a path it never runs, which is Miri's own real, stated limitation.

## A.4 Terms and notation (continuing Chapters 1–29's vocabulary)

Everything in Chapters 1–29 §A.4 still applies. This chapter adds:

- **Soundness**: the real property that no *safe* caller can ever trigger undefined behavior through a given API, a stronger, real claim than "none of today's callers happen to misuse it."
- **Safety contract**: the real, documented set of preconditions (a `# Safety` doc comment on an unsafe function; a `// SAFETY:` comment at an unsafe block) that must genuinely hold for that unsafe code to behave as intended.
- **Validity invariant**: the real constraint on which bit patterns are a legal value of a given type (for example, `bool` is only ever `0` or `1`); constructing a value that violates it is undefined behavior the instant it exists, whether or not it is ever read.
- **Provenance**: the real, additional information a pointer carries beyond its numeric address, tracking which real allocation it is actually permitted to access; the strict-provenance APIs (`addr()`, `with_addr()`, stable since Rust 1.84) let a program work with a pointer's own address without ever fabricating provenance it was not given.
- **UB-detection path limitation**: the real, stated limit of a dynamic checker like Miri: it can only catch a violation on a path the program actually executes during that run, never one hiding in a branch the run never takes.

Narration words (continuing the convention: no digits, symbols, or code-style names spoken): "a documented promise the unsafe code makes" for a safety contract; "no caller using only the safe surface can ever cause this" for soundness; "which bit patterns are even allowed to exist" for a validity invariant; "which real allocation a pointer is actually permitted to touch" for provenance; "it only catches what the run actually takes" for the path limitation.
