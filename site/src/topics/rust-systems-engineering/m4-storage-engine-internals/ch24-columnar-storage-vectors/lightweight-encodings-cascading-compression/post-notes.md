## Outcomes

- Build a real run-length encoder and decoder, over one of topic 62's own column-major columns.
- Measure that the encoding genuinely wins big, by compression ratio, on a skewed, repetitive column.
- Measure that the identical encoding genuinely loses on a uniformly random column of the identical length.
- Measure that decode work per value is itself genuinely data-distribution-dependent, and that both encoded columns decode back to their exact original values.
- State, from Apache Parquet's own format documentation, the real trade-off between an encoding's compression ratio and its own processing cost.

## Internals

The uniformly random column measured here is generated by a self-contained, deterministic xorshift generator rather than any external randomness source, so the measured loss is exactly reproducible on every run rather than merely plausible. Decode work is measured as the real number of run-headers a decoder has to iterate over per output value, a genuine structural property of the encoded representation, rather than a wall-clock timing measurement that would be noisy in a sandboxed build; both the skewed and the random column's encoded forms are independently decoded and checked for an exact round trip against their original values, so the compression-ratio claims are not made at the cost of silently losing data.

## In production

Apache Parquet's own format documentation states the real trade-off directly, in its own words: the format supports several compression codecs, covering different areas in the compression ratio and processing cost spectrum. Its own encodings documentation names run-length encoding directly as a combination of bit-packing and run-length encoding, used to store repeated values more efficiently; the same page also documents delta encoding, which stores a bit width per miniblock and is less sensitive to variations in the size of encoded integers, effectively subsuming run-length encoding as a special case. Beyond the single encoding measured here, real systems cascade several of these choices together (BtrBlocks, SIGMOD 2023), apply FSST specifically to strings (VLDB 2020) and ALP specifically to floating-point values (SIGMOD 2024), and increasingly execute queries directly against the compressed bytes rather than decoding first; newer file formats beyond Parquet, such as Vortex and Lance, build on exactly this foundation.

## The frontier

This topic measures the single, foundational run-length case the broader data-distribution-dependent principle rests on; delta, dictionary, frame-of-reference and bit-packing encodings, along with cascading compression and execution directly on compressed data, are named in prose here rather than separately measured, since this topic's own job is the principle beneath all of them. All of this topic's own measured claims run entirely on plain in-memory Rust structs and vectors, with no file, network, or root access needed.
