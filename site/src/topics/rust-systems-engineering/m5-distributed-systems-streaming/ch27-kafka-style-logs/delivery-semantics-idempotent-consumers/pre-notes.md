- **At-most-once / at-least-once / exactly-once**: real delivery semantics defined by exactly where publishing, consuming, and committing an offset can independently fail, never by anything the network itself does.
- **Idempotency key**: a real producer id plus a real, increasing sequence number, letting a broker or consumer detect and discard a genuine duplicate of a message it has already seen. *Where you meet it:* a consumer checks this key before applying a side effect, not just a broker checking it before writing to the log.
- **Redelivery vs. duplicate effect**: the real distinction this topic's own code measures directly — a message arriving twice is not the same fact as its own side effect running twice; an idempotency key only ever removes the second one.
- **Downstream side effect**: a real effect (a payment, an email, a ledger update) that a broker's own transaction boundary cannot undo once it has already happened outside Kafka, which is why a consumer needs its own dedup even when the broker offers transactional guarantees.
