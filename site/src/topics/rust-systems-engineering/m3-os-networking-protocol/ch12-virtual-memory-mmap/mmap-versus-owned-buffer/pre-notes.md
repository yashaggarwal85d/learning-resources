- **Double caching**: the kernel's own page cache and an application-level cache holding the same file's bytes at once, with no way for either to learn what the other is doing. *Where you meet it:* a real mapping's own residency, measured next to a second, independently read copy.
- **Direct I/O (`O_DIRECT`)**: bypassing the page cache entirely, in exchange for hard alignment and completion constraints the kernel enforces strictly. *Where you meet it:* a misaligned buffer's read failing outright, and an aligned one succeeding.
- **The paper's own four failure classes**: transactional safety, I/O-stall unpredictability, error handling, and TLB-shootdown cost — Crotty, Leis & Pavlo's own argument for why most DBMSs own their buffer pool instead of mapping a file directly.
- **An owned buffer pool**: an application-managed cache of file contents, with its own eviction policy, durability ordering, and error handling — the alternative most DBMSs choose over mapping the file directly, except in a narrow, read-mostly case.
