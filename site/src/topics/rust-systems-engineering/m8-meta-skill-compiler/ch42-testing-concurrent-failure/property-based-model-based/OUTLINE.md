## Storyboard (8 steps, 3 predict/reveal pairs)

1. **BugPredict** — A real allocator checks only that each new slot's own real length fits the page, never checking where that slot actually starts. A real property test throws a large, random space of real insert sequences at it. Does a hand-picked example test, checking only the cases its author thought of, actually need to find this bug, or does the random search find it anyway? Options: a hand-picked example would have found it just as easily; the random search finds it, genuinely, without anyone having to think of the exact case (correct); only if the sequence is extremely long.
2. **BugReveal** — Measured: the real property test, run against hundreds of real, randomly generated insert sequences, genuinely finds a sequence that violates the bounds invariant, and shrinks it down to a real, minimal failing case. No separate takeaway here (this is the reel's own "from" step for the phone swipe test; its takeaway moves to step 7, the connecting step, below).
3. **ShrinkPredict** — The real, random search that found the bug started from sequences up to thirty inserts long. Does the real counterexample it actually reports stay that long, or does it get smaller? Options: it stays exactly as long as whatever random sequence happened to trigger it; it genuinely shrinks down to a much smaller, minimal case (correct); it only shrinks if the bug is triggered early in the sequence.
4. **ShrinkReveal** — Measured: the real, reported counterexample shrinks down to a handful of inserts whose real total lands just barely over the page's own real capacity, the smallest real overrun `proptest` could find, not the much longer sequence that happened to trigger the search. Takeaway: shrinking turns a real, messy failure into its own smallest real cause, not a lucky guess closer to the actual bug.
5. **CheckedPredict** — The identical real property test, run against the checked, correct insert instead. Does it pass because this topic happened to pick easy random cases, or because the real invariant genuinely holds? Options: it only passes by luck, on these particular random cases; it genuinely holds across every one of the real, random cases tried (correct); it depends on the capacity chosen.
6. **CheckedReveal** — Measured: the identical real bounds check, run against hundreds of real, randomly generated sequences, genuinely passes every single one against the checked insert, the same real invariant that found a bug in the naive version moments earlier. Takeaway: a property test's own real confidence comes from how many real, different cases it actually tried, not from any one case alone.
7. **DocsReveal** — The `proptest` crate's own README states this directly, in its own words: it tests that real properties hold for arbitrary inputs and, on failure, automatically finds the real, minimal case that reproduces the problem. Does this topic's own two measured runs match exactly what that sentence describes? Takeaway (moved here from step 2): a shrunk counterexample finds what one, hand-picked example genuinely cannot.
8. **Recap** — A real property test tries far more cases than any one person would think to write by hand, and shrinks whatever it finds down to its own smallest real cause; a real, stateful comparison against a simpler reference model catches disagreement the identical way, across a real, random sequence of operations, rather than the one sequence someone happened to test.
