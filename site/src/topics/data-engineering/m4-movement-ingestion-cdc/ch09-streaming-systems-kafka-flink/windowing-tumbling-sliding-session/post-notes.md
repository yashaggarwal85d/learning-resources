## Outcomes

A real toy aggregator confirms a half-overlap sliding window nearly doubles the number of
assigned element-copies versus an equal-size tumbling window on the same stream. A real session-
window model confirms two separate sessions merge into one the instant a late record lands inside
the gap between them. A real global-window model confirms the default trigger never fires, while
a custom count-based trigger does. A real pane-tracking model confirms live pane count rises while
the stream runs and falls to zero once the source goes idle. All four are measured directly
against the models' own state, not asserted.

<section data-section="production">

## Production failures this topic warns about

**Assuming a sliding window costs what a tumbling window costs.** Switching window types without
re-checking state cost can silently multiply memory use by the overlap factor, with no warning
until the job runs out of memory.

**Forgetting a session window can retroactively change its own boundaries.** A late record can
merge two sessions that already looked final, changing the aggregate a downstream consumer already
saw.

**Using a global window without a custom trigger.** Left to the default trigger, a global window
simply never emits anything, since it has no natural end for a watermark to pass.

</section>
