## Red team

- **CHAPTER.md's own syllabus text is wrong on two points, both corrected in this topic** (same
  pattern as topic 28's date correction): (a) delta-rs is not a Delta Kernel connector, it is a
  separate implementation Kernel exists as an alternative to; (b) Variant shredding is not fully
  out of preview in Delta 4.3 -- it is still preview-named with an unenforced opt-in flag.
- Delta Kernel itself is not built in code here -- no Python bindings exist for it in this
  sandbox. Its description is sourced and narrated, not executed.
- The real protocol-feature demos (deletion vectors, row tracking, Variant type) enable the
  *table feature flag* via delta-rs's own API; they do not re-derive the encoding each feature
  uses on disk (deletion vectors' bitmap format, Variant's binary encoding) -- those were already
  built by hand in topics 8 and 14-15. This topic shows the *protocol-level switch*, not a second
  implementation of each feature's encoding.
- Collations and the Geospatial table feature are confirmed as Delta Kernel features specifically
  in the 4.2.0 release notes; this topic does not independently verify whether Delta Spark itself
  (as opposed to Kernel) supports them at the same version.
- Type widening's and the identity/generated-column facts come from Delta's own release notes and
  docs pages, not independently re-derived from the Delta protocol spec itself.
- No deltalake/delta-rs library was used anywhere else in this chapter until this topic --
  deliberately, since this topic's whole point is to use it directly, for real, with no Spark.

## Scope boundary

This topic states Delta Lake's current 4.x release line and its headline features precisely
(with version numbers and the Kernel-vs-Spark distinction where the primary source draws one), and
uses `deltalake`/delta-rs directly to write, append, time-travel read, and enable real protocol
table features on a local Delta table -- no Spark cluster anywhere. It does not build Delta Kernel
itself (no Python bindings available), does not re-implement collations' string-comparison
semantics or the Geospatial feature's on-disk encoding, and does not re-derive Variant's own
binary encoding (already built in topic 8) -- only the protocol feature-flag mechanism that turns
each on.
