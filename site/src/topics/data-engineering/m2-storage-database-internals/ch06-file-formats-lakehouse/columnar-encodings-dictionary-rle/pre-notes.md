- **Row group, column chunk, page**: Parquet's own file hierarchy, from this chapter's anatomy topic. *Where you meet it:* every encoding in this topic lives inside a page — dictionary and data pages, specifically — which is the unit this topic actually measures.
- **Dictionary page vs. data page**: the two-page shape a dictionary-encoded column chunk uses, from this chapter's anatomy topic. *Where you meet it:* this topic's dictionary section is that same shape, now with the real fallback rule and its own cardinality threshold added.
- **PLAIN encoding**: storing each value as its raw, unencoded bytes, from this chapter's anatomy topic, which used it for every column. *Where you meet it:* the baseline every encoding in this topic is measured against — bytes saved, or not, relative to PLAIN.
- **Columnar layout**: storing one column's values together, from this chapter's row-vs-columnar topic. *Where you meet it:* every encoding here depends on seeing a whole column's worth of values before choosing how to lay any of them out — a row-at-a-time writer never gets that chance.
- **Variable-length integer encoding (varint)**: packing an integer into as few bytes as its actual magnitude needs, general computing background. *Where you meet it:* this topic's header fields (block size, miniblock count, value count) are all stored as ULEB128 varints, the same primitive Thrift itself uses.
- **General-purpose compression (DEFLATE/zlib)**: a byte-level compressor that looks for repeated sequences, general computing background. *Where you meet it:* this topic's "encode first, compress second" step runs zlib on top of an already-encoded column to show the two layers are independent.
