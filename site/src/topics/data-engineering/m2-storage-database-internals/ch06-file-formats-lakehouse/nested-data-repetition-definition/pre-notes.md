- **Row group, column chunk, page**: Parquet's own file hierarchy, from this chapter's anatomy topic. *Where you meet it:* repetition and definition levels are written inside the same pages those topics already described, ahead of the actual values.
- **Dictionary page vs. data page, and the five encodings**: from this chapter's prior two topics. *Where you meet it:* this topic's level streams are themselves RLE-encoded, the same hybrid this chapter already covered for dictionary indices and booleans.
- **PLAIN encoding as a baseline**: from this chapter's anatomy topic. *Where you meet it:* a flat (non-nested) column needs no levels at all — the baseline this topic's nested columns add structure on top of.
- **Required vs. optional vs. repeated fields**: a schema's own way of saying whether a field must appear, may be missing, or may appear more than once, general schema-design background. *Where you meet it:* every rule in this topic (how many definition levels a path needs, whether repetition levels exist at all) is computed directly from this three-way distinction.
- **A null bitmap / validity bitmap**: one bit per value, marking whether it's present, general database background. *Where you meet it:* Arrow's own nested layout in this topic is built from exactly this primitive, one per nesting level, contrasted directly against Parquet's single shared level stream.
- **Buffers as a storage model (a flat run of bytes, interpreted by a schema)**: general columnar-storage background. *Where you meet it:* Arrow's offsets buffer and ORC's length stream in this topic are both just flat integer buffers, the same primitive this topic's own Parquet levels are packed into.
