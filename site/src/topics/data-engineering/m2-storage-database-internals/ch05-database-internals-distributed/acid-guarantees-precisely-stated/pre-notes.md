- **Transaction**: a group of database operations the application asks to be applied as one unit, background from earlier topics in this chapter. *Where you meet it:* the subject every one of the four letters is a guarantee about.
- **CHECK constraint**: a declared rule a table enforces on every row (e.g. a column can't go negative), background from this chapter's own storage topics. *Where you meet it:* the concrete example this topic's own consistency split is built on.
- **Write-ahead log (WAL)**: taught directly in §5.1's own write-ahead-logging topic — a sequential, append-only log of every write, flushed before the data it describes. *Where you meet it:* the real mechanism durability's own promise is built on.
- **MVCC (multiversion concurrency control)**: taught directly in §5.1's own LSM and Postgres topics — each transaction sees a consistent snapshot rather than the live, changing table. *Where you meet it:* the real mechanism isolation's own promise is built on.
- **Commit / rollback**: committing makes a transaction's changes permanent; rolling back discards them entirely, background from earlier topics. *Where you meet it:* the boundary every one of this topic's own measurements is taken across.
