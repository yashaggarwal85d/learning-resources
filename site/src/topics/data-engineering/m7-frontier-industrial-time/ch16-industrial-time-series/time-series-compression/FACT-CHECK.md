## Red team

- **Is the simplified Chimp implementation an honest stand-in, given it doesn't reliably beat Gorilla?** Yes — `OUTLINE.md` discloses explicitly that `chimp_encode` omits the paper's §4.1.4 leading-zero-reuse refinement, and `examples.py` makes no blanket "Chimp beats Gorilla" assertion; the only Chimp-specific assertions are about Chimp128's wider window winning on the repeating-pattern regime, which is what the implementation actually and reliably does. The paper's own "outperforms all earlier techniques" claim is kept as a quoted claim in `SOURCES.md`, not restated as this topic's own measured result.
- **Are the three synthetic regimes representative, or chosen to force a predetermined conclusion?** Each regime is built to isolate one property the syllabus names, not to produce a specific number: regular/slow mirrors the paper's own description of its data (mostly-unchanged values, regular timestamps); noisy float has irregular timestamps and high-entropy values by construction (a congruential sequence, not tuned to any codec); decimal/regular has two-decimal-place values at a regular rate, which is ALP's and Chimp128's stated favorable case, not Gorilla's. The claim under test in each case ("the ratio is a property of the data") only holds up because the same unmodified encoder functions are run against all three — no encoder was retuned per regime.
- **Does reproducing only 2 of the paper's examples (not every number in the chapter's scope line) understate verification?** The two reproduced examples (9-bit delta-of-delta, 14-bit XOR) are the paper's own worked numerical examples, the only ones specific enough to assert as exact bit counts; the 96%/51% figures are aggregate statistics over Facebook's production trace, which this environment doesn't have access to, so they are quoted (claim 6, 7 above) rather than re-derived — consistent with `CHAPTER.md`'s framing that the topic reproduces "the paper's own example," singular, not its full production trace.
- **Is the Chapter 15 gap (`edge-buffer-sizing-from-outage`, `manufacturing-telemetry-platform-design`) handled consistently with the prior two gaps (topic 6's Chapter 10/11 gap, topic 10's Chapter 5 sketch-id gap)?** Yes — same pattern: verified by `grep` against `registry.ts` (Chapter 15 extends only through §15.3) before writing `OUTLINE.md`, the missing ids are omitted from `uses`, and the gap is disclosed in both `OUTLINE.md` and `SOURCES.md` rather than fabricated or silently dropped.
- **Does running ALP only via DuckDB's own codec (no standalone ALP library) understate the claim?** No — `SOURCES.md` states explicitly that no ALP library is installed in this environment, and that DuckDB's own default float codec is "the production implementation of the same idea" being measured instead; the paper's own claims (the Zstd comparison, the decimal-encoding description) are kept as quotes, not reproduced as this topic's own measurement.
