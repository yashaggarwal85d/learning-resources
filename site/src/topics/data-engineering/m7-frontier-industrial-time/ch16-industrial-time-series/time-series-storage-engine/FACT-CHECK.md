## Red team

- **Is simulating these engines instead of running real Prometheus/TimescaleDB/InfluxDB3 instances a weaker form of evidence?** For Prometheus, this environment has no installable binary and the GitHub releases host isn't reachable (checked directly, documented in `OUTLINE.md`); for TimescaleDB, InfluxDB 3, Thanos, Mimir and VictoriaMetrics, no instance exists in this sandbox either. Every constant the simulations use (two-hour blocks, 128MB WAL segments, the capacity formula, the out-of-order rule, the chunk-exclusion behavior, the WAL/buffer/Parquet timings) is quoted directly from each engine's own documentation in `SOURCES.md`, and the simulation's job is only to check that the documented *rule* behaves as described, not to claim a real system's exact performance numbers.
- **Does the plant's capacity-formula result depend on an arbitrary sampling interval choice?** The 10-second sampling interval is stated explicitly as a modeling choice, not sourced from any particular document; the formula itself, and the series count it multiplies (1297, carried over from topic 12's own measurement), are the parts under test — the specific disk-size output is illustrative of how the formula behaves, not a claim about what the real plant's exact interval is.
- **Is the InfluxDB 3 pipeline simulation's cutoff/tail bookkeeping an accurate model of the real system, or a simplification that could mislead?** It's disclosed as a simplification: the real system's buffer management involves additional detail (per-partition and per-table bookkeeping, write validation, memory-pool accounting) this topic's own pipeline does not model; what's checked and asserted is only the documented timing cycle (every second to WAL, a 15-minute queryable window, a 10-minute Parquet cycle keeping 5 minutes in memory), which the simulation reproduces exactly.
- **Does naming Thanos, Mimir and VictoriaMetrics without running any of them overstate the "common pattern" claim?** No — the claim being tested (the Prometheus block format pushed to object storage behind a stateless query layer) is checkable directly from each project's own architecture description quoted in `SOURCES.md`, without needing to run any of the three; `FACT-CHECK.md` marks every claim about them "named only, not run."
