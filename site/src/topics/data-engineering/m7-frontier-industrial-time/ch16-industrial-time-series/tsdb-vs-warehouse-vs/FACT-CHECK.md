## Red team

- **Is measuring four access paths only on DuckDB, instead of on each named engine, a weaker form of evidence than CHAPTER.md's own "measured or sourced" standard asks for?** CHAPTER.md's own text allows exactly this: "the builder measures the three access paths on DuckDB/Parquet against a synthetic week ... rather than asserting them" — DuckDB is explicitly the measurement stand-in this topic's own scope calls for, with every vendor-specific claim (MergeTree's granules, QuestDB's tiers, InfluxDB 3's caches) kept as a quoted, sourced claim rather than restated as this topic's own measured result.
- **Does the capacity-and-cost chain's bytes-per-point figure for the lakehouse tier (measured from DuckDB's own Parquet output) overstate what a real lakehouse table format would achieve?** The measured figure is DuckDB's own default Parquet writer on synthetic, effectively-random values with no real-world compressibility (deliberately, so the number isn't flattering) — a real deployment's actual values would very likely compress better, which this topic does not claim to have measured; the number stands only for the chain's own arithmetic, not a promise about any specific production system.
- **Is the tier-overlap simulation's "duplicated points" count a real operational cost, or just an artifact of the toy export-lag parameter?** The mechanism is general: any pipeline that exports a day's data to the lakehouse some fixed number of days after that day ends will have exactly this overlap for exactly that many days' worth of points, regardless of the specific lag chosen — the simulation's own assertions check the mechanism (nonzero, bounded) rather than a specific lag's exact count.
- **Does omitting `analytical-serving-layers` understate what this topic depends on?** The Chapter 5 id is named by CHAPTER.md as in-course background on analytical serving layers in general; this topic's own access-path measurements and capacity chain don't depend on that background to run or to be checked, and the gap is disclosed in `OUTLINE.md`/`SOURCES.md` rather than silently dropped.
