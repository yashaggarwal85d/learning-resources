- **Bridge table**: a table that resolves a many-to-many relationship between a fact and a dimension (or between two dimensions), with one row per linked value. *Where you meet it:* a table of order-to-promo-tag pairs, letting one order carry several tags at once.
- **Weighting factor**: a value assigned to each bridge row, summing to one within its group, that prevents a measure from being counted once per linked row. *Where you meet it:* a 0.5/0.3/0.2 split across an order's three promo tags, multiplied into the amount before summing.
- **Double counting**: the inflated total that results from joining through a bridge table and summing a measure without applying a weighting factor. *Where you meet it:* an order's amount reported as three times its real value because it was joined to three tags with no weight applied.
- **Flattened hierarchy bridge**: a bridge table holding one row for every ancestor-descendant path in a ragged hierarchy, computed once so later queries need no recursion. *Where you meet it:* a product-category tree of uneven depth, pre-expanded into every possible path so "everything under this category" is a plain filter.
