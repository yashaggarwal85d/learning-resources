- **Hub**: a table holding only a business key, a surrogate or hash key, and origin metadata — nothing descriptive. *Where you meet it:* `hub_customer`, holding a customer number and nothing about the customer.
- **Link**: a table capturing the relationship between two or more hubs, often many-to-many. *Where you meet it:* `link_order_customer`, connecting an order hub to a customer hub.
- **Satellite**: a table holding the descriptive, time-tracked attributes of a hub or link, appended to rather than overwritten. *Where you meet it:* `sat_customer_address`, gaining a new row every time a customer's address changes.
- **Hash key**: a surrogate key computed deterministically from a business key (typically MD5 or SHA-256), rather than assigned by a sequence. *Where you meet it:* the same customer number hashing to the identical key no matter which loading process computes it.
- **Point-in-time (PIT) table**: a table that pre-resolves which satellite row was current as of a given date, built at load time instead of being recomputed on every query. *Where you meet it:* answering "what did this customer look like on this date" without a correlated subquery.
- **Bridge table**: a table that pre-computes a query path crossing several links at once, for queries that would otherwise have to walk that path every time. *Where you meet it:* a report that would otherwise join through five link tables to answer one question.
