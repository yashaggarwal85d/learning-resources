- **Incremental strategy**: the specific way dbt applies new or changed rows to an existing table (append, delete+insert, merge, insert_overwrite, microbatch), rather than rebuilding it. *Where you meet it:* the lab's own four real strategies, run against the same fact table, plus the fifth (`insert_overwrite`) this project's own adapter cannot run at all.
- **Lookback**: a fixed window behind the table's current high-water mark, meant to catch late-arriving rows. *Where you meet it:* a real correction to an old row, missed by every lookback window in this lab, caught only by `--full-refresh`.
- **on_schema_change**: the config controlling what happens when an incremental model's own columns change. *Where you meet it:* the lab's own three-stage demonstration — silently dropped, added but unbackfilled, or fully backfilled.
- **Snapshot**: dbt's own automatic implementation of type-two slowly changing dimensions over a mutable source table. *Where you meet it:* the lab's own customer snapshot, run twice around a real region change.
- **Timestamp vs check strategy**: whether a snapshot's own valid-from time comes from the data's own `updated_at` column, or from whenever dbt happened to run. *Where you meet it:* two real snapshot tables, read directly, showing two different valid-from values for the same change.
