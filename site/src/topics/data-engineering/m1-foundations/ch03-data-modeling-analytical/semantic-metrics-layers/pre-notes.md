- **Semantic layer**: a tool that compiles one metric definition to SQL consistently, no matter which BI tool or question asks for it. *Where you meet it:* MetricFlow, built hands-on in this topic's own lab, compiling one `revenue` metric two different ways.
- **Entity**: a semantic model's declared join key — an explicit traversal path to another table, never inferred from matching column names. *Where you meet it:* the lab's own automatic join, which only happened because a relationship was declared ahead of time.
- **Time spine**: a dedicated base table built specifically for time-based joins and aggregations, required before any time-based metric can compile. *Where you meet it:* a real build failure this lab hit directly, until one was added.
- **DRY (Don't Repeat Yourself)**: MetricFlow's own stated design principle — one metric definition should work everywhere it possibly can, rather than being redefined per tool or per report. *Where you meet it:* the entire reason the lab's two-queries-from-one-definition result matters.
