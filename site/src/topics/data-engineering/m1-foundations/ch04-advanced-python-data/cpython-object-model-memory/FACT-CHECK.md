## Lab claims (executed, not just sourced)

- **A list of boxed ints costs measurably more than the identical values packed into a native buffer.** `examples.py`'s `boxed_vs_packed_int_list()` measures 36,056 bytes (list shell plus every distinct boxed int object, deduplicated by `id()` to avoid double-counting CPython's own small-int cache) against 8,080 bytes for an `array.array('q', ...)` of the same 1,000 values — a ratio of about 4.5× on a representative run, asserted to stay above 3×.
- **`__slots__` removes the per-instance `__dict__` entirely, not just shrinks it.** `examples.py`'s `dict_instance_vs_slots_instance()` measures 344 bytes (instance plus its own `__dict__`) against 56 bytes for the identical three-field `__slots__` class — about 6.1× — and confirms directly that the slotted instance has no `__dict__` attribute at all (`hasattr` returns `False`), not merely a smaller one.
- **The specializing adaptive interpreter's effect is directly visible in real disassembly, not just claimed.** `examples.py`'s `specializing_interpreter_bytecode()` disassembles the identical function before any call (generic `BINARY_OP`), after 200 int+int calls (`BINARY_OP_ADD_INT`), and — a second, freshly defined copy of the function — after 200 str+str calls (`BINARY_OP_ADD_UNICODE`). The specialized opcode is genuinely absent before warm-up and genuinely present after.
- **Mixing argument types costs real, measurable extra work, not just "some overhead in theory."** `examples.py`'s `consistent_vs_mixed_type_calls()` runs the identical function the identical number of times with one consistent type throughout vs. alternating int/float, and measures the alternating run costing about 1.7× the consistent run on a representative run (asserted to stay above 1.1×) — a direct, measured instance of PEP 659's own "cost caused by mis-specialization."
- **This sandbox's own CPython build has neither the experimental JIT nor free-threading enabled.** `examples.py`'s `jit_build_status()` checks directly: `sys._jit` is absent and `sysconfig.get_config_var('Py_GIL_DISABLED')` is `0`. Every claim in this topic about the JIT or free-threading's own effect is therefore disclosed as sourced-only from PEP 659/PEP 744/the 3.13 release notes, never asserted as locally measured.
- **A per-row Python loop is genuinely tens of times slower than an equivalent vectorized call, even measured charitably.** `examples.py`'s `loop_vs_vectorized_speedup()` times the identical arithmetic as a plain Python `for` loop and as a Polars `Series` expression (best-of-three each, the vectorized call warmed up once before timing so the comparison isn't dominated by one-time compilation cost) and measures a speedup in the tens-of-times range across repeated runs — inside the syllabus's own "10–100×" range, with the vectorized call's own real first-call overhead (`vectorized_first_call_overhead()`) disclosed separately rather than hidden inside the headline number.

## Red-team analysis of the three predicts

- **Predict 1 (step 3):** the tempting wrong answer ("a list of a million plain ints costs about the same either way, since they're just numbers") is directly refuted by the measured 4.5× ratio — the wrongness is specifically the assumption that "just a number" has no header cost, which SOURCES.md's `PyObject` quote already rules out before the lab even runs.
- **Predict 2 (step 6):** the tempting wrong answer ("the interpreter runs the same bytecode regardless of type, since Python is dynamically typed throughout execution") is directly refuted by the real disassembly — the bytecode itself changes shape (`BINARY_OP` → `BINARY_OP_ADD_INT`/`BINARY_OP_ADD_UNICODE`) depending on what actually showed up, which is specifically what "adaptive" means in PEP 659's own abstract.
- **Predict 3 ("Prove it", step 12):** the tempting wrong answer ("specialization still helps the same amount no matter how the types are mixed, since the interpreter adapts either way") is directly refuted by the measured 1.7× slowdown under alternating types — adapting is not free, and PEP 659's own text already names this cost ("the amount of additional work caused by mis-specialization") before the lab measures it.
