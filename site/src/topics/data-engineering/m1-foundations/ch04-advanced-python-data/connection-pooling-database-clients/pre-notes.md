- **Connection pool**: a set of already-open connections, handed out to callers and returned when they're done, instead of opening a fresh one per request. *Where you meet it:* the whole topic; the setup-cost reveal is the reason one is worth having at all.
- **Pooling mode**: how a pool decides which physical backend connection a client's logical connection actually uses, and for how long. *Where you meet it:* the predict step and both prepared-statement reveals, which contrast two of PgBouncer's three modes.
- **Physical backend vs. logical client connection**: the client's own connection to the pool can stay open the whole time while the pool quietly hands it a different physical database connection underneath, transaction by transaction. *Where you meet it:* the reproduced prepared-statement caveat — this is exactly the distinction the predict question tests.
- **Prepared statement**: a parsed, planned query, stored once and run repeatedly by name instead of being reparsed each time. *Where you meet it:* the predict question and its reveal, both reveals this topic builds around.
- **Server-side cursor**: a cursor that keeps a query's unfetched rows on the server, letting a client pull them in batches instead of all at once. *Where you meet it:* the server-side-cursor reveal, contrasted directly against fetching a result whole.
