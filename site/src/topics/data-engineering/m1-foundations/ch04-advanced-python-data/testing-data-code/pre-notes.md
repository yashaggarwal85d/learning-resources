- **Unit test**: a test on the smallest input that still exercises one function, not a full dataset. *Where you meet it:* the unit-test reveal, the narrowest of this topic's five layers.
- **Property-based test**: a test that generates many inputs itself and checks one invariant across all of them, rather than taking a single input you hand it. *Where you meet it:* the property-test reveal and the predict step built around it, reusing the previous topic's idempotency-key rule.
- **Producer/consumer contract test**: a test where a shared description of one request and its minimal expected response builds a real mock server, which the consumer's own real code is then tested against. *Where you meet it:* the contract-test reveal.
- **Ephemeral dependency**: a real, disposable copy of a dependency (such as a database) spun up just for one test's duration instead of mocked outright. *Where you meet it:* the integration-test reveal, including the one piece of tooling this sandbox couldn't run directly.
- **Golden-output test**: a test that records a deterministic system's real output once, then diffs every later run against that recorded file. *Where you meet it:* the golden-master reveal.
