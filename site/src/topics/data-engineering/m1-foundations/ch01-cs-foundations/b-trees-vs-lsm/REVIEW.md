## 2. Unsupported numbers / code-correctness

- **Real bug: wrong column name in the lab's SQL.** `index.mdx`, Lab section: `SELECT level, root, fast_level FROM bt_metap('orders_pkey');`. PostgreSQL 18's `pageinspect` documentation (source 8 above) shows `bt_metap`'s actual output columns are `magic, version, root, level, fastroot, fastlevel, last_cleanup_num_delpages, last_cleanup_num_tuples, allequalimage` — the column is **`fastlevel`**, with no underscore. As written, this query raises `column "fast_level" does not exist` in a real PostgreSQL session. This is exactly the kind of claim the "Try it" lab is supposed to let a learner run — fix the column name before this ships.
- **Unsupported number: the "2× device write amplification" multiplier.** Internals, "Two amplifications multiply": "a 33× LSM write amplification over a 2× device write amplification is ~66× flash writes per logical byte." The 33× is sourced (RocksDB's own worked example, verified above); the 2× device figure has no citation and isn't marked "measure in build" or flagged as illustrative — it reads as an asserted fact about SSD write amplification in general, which varies substantially by device, workload and over-provisioning. Either cite a source for a representative device figure or mark it "measure in build" / "illustrative" the way the fan-out estimate a few paragraphs earlier is marked.
- **Minor rounding: $\log_{1000}(10^8)$.** The table gives $\log_f N$ = 2.66 for N = 100,000,000, f = 1,000. The exact value is $8/3 = 2.6\overline{6}$, which rounds to **2.67** at two decimal places, not 2.66 (the draft appears to have truncated rather than rounded). Doesn't change the ceiling (3 levels either way), but it's a small, avoidable arithmetic slip in a table whose whole point is precise logarithm arithmetic.
- All other numbers check out: the height table's other three rows (log₂₅₆(10⁸) ≈ 3.32 → 4 levels; log₅₁₂(10⁸) ≈ 2.95 → 3 levels; log₁₀₀₀(10⁹) = 3.00 exactly → 3 levels) were independently recomputed and are correct; the ~20-byte entry estimate and "a few hundred" fan-out are both explicitly marked "measure in build"; the 8 KB PostgreSQL page size is a stated, well-known default.
