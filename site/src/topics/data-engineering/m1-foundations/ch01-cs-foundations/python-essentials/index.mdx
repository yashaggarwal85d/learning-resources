<section data-section="internals">

## A little deeper

- **Where the default lives.** A default value is evaluated when `def` runs and stored on the function object, in `append_one.__defaults__`. That's why every call sees the same list. Dataclasses refuse the same trap outright: a field declared as `xs: list = []` raises `ValueError` ("use default_factory"); write `field(default_factory=list)`.
- **Generators keep their frame.** A generator object holds its paused stack frame, so local variables survive between values. Iteration is a protocol: `iter()` returns an iterator, `next()` advances it, and `StopIteration` ends it; `for` loops, `sum()` and `list()` all speak it.
- **Context managers are `__enter__` and `__exit__`.** `with` calls `__exit__` however the block ends. If `__exit__` returns a true value the exception is suppressed, which is rarely what you want. `contextlib.ExitStack` manages a variable number of resources, such as one file per partition.
- **Decorators with arguments** are factories: `@retry(times=3)` calls `retry(times=3)`, which returns the actual decorator.
- **Annotations are data.** Hints are stored in `__annotations__` and ignored at runtime. Python 3.14 changed *when* annotations are evaluated (deferred, PEP 649 and PEP 749), which matters to libraries that read them; it does not make Python enforce them.

</section>

<section data-section="production">

## In code review

- `def f(..., opts={})` or `=[]`: a shared mutable default. Use `None`, or `default_factory` in dataclasses.
- `f.read()` or `readlines()` on input of unknown size: stream it with iteration or a generator.
- `open()` or a connection without `with`: a leak waiting for the first exception.
- A decorator without `functools.wraps`: logs, tracebacks and introspection now say `wrapper`.
- Type hints with no checker in CI: documentation that can silently drift from the code.

</section>
