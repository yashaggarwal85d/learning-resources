## 2. Unsupported numbers

None found as unsupported; two small unit-consistency nits:

- **MB vs. MiB mixed for the same quantity.** Internals, "Throughput and latency are different axes": "a path with a 75 MB BDP, a single stream needs a 75 MiB window to run flat out; one default-tuned stream will crawl. The fix is either a bigger window or N parallel streams whose windows sum to the BDP: ten streams each need only about 7.5 MB in flight." The BDP table computes the cross-region BDP in decimal MB (≈75 MB, consistent with the chapter's stated convention that network volumes are decimal bytes), but the very next sentence calls the matching window "75 MiB" (binary) — 75 MB (75,000,000 bytes) and 75 MiB (78,643,200 bytes) differ by about 4.6%, so the two uses of "75" aren't quite the same number once the units are taken seriously. The follow-up "ten streams... about 7.5 MB" correctly reverts to MB. Pick one unit for this quantity throughout the paragraph.
- **Loosely stated formula.** Internals, "Throughput and latency are different axes," last sentence: "to reach a bandwidth target when each request waits α before its first byte, you keep **concurrency = throughput × α** requests in flight." Dimensionally this only works if "throughput" here means a target *request rate* (requests/second), not the bytes/second throughput the rest of the paragraph is using — Little's law gives in-flight-items = arrival-rate × time-in-system, and the object-storage topic's own worked example reaches its "about fourteen" concurrent-request figure by dividing a bytes/second target by bytes/second-per-request, not by multiplying bytes/second by α. The sentence is a reasonable one-line callback to Little's law and isn't asserting a wrong number (none is given here), but as written it's not quite the same formula as the one actually used to get "about fourteen" in the object-storage topic it's referencing — worth tightening the wording (e.g. "keep enough **requests** in flight that arrival rate × α matches your target concurrency") so a careful reader doesn't try to plug bytes/s into it directly.
- Every number that **is** independently checkable was recomputed and is correct: both rows of the BDP/throughput table (≈625 KB / ≈131 MB/s ≈1.0 Gbit/s for same-AZ; ≈75 MB / ≈1.1 MB/s ≈8.7 Mbit/s for cross-region, and "under one tenth of one percent" = 0.087%, correct); the shuffle/broadcast re-pricing (9.9 GB/machine ÷ 1.25 GB/s ≈ 8 s; 0.1 GB/machine ÷ 1.25 GB/s ≈ 0.08 s; both ratios exactly 100×); and the dollar figures (990 GB × $0.02/GB round-trip-equivalent ≈ $19.80 ≈ "$20"; 9.9 GB × $0.02/GB ≈ $0.198 ≈ "$0.20", same 100× ratio as the bytes).
