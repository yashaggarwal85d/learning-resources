## Explanations and predict questions, red-teamed

- **Step 5 (which shell).** Holds. Edge cases tried: jq 1.8.1 (the November image) still exits 2. A workflow-level `defaults.run.shell` would change the answer, but the frame sets none. On Windows the default is `pwsh`, which the frame's `ubuntu-latest` rules out. If bash were missing, `sh -e {0}` gives the same 0. "1" and "127" are no command's status here.
- **Step 7 (version).** Holds once the cards are fixed (D). 2.0.0 is forced if the columns are the declared API (rule 8). 1.6.0 would be right only for an additive change (keep `status`, add `order_status`, deprecate), which the card's "rename" excludes. 1.5.0 can't be rebuilt (rule 3).
- **Step 8 (drift).** Holds. A `cache: pip` restore doesn't change resolution: pip still picks the newest match (README quote). Pre-releases can't sneak in: 2.0.0 is final, and pip 26's only-match rule doesn't apply while 1.5.0 matches. A Python-version or yank edge doesn't arise (pure-Python `py3-none-any` wheels, a local index). The wrong options are wrong for the stated reasons (F).
- **Step 3.** Holds: `Paid` passes on the bug because `lower()` fixes case. Caption fixed (J).
- **Step 4.** Holds as simplified. Steps with `if: always()`/`failure()` and actions' post steps are the exceptions, covered in the Deep dive.
- **Step 6.** Holds. Seeds 0–19 are fixed seeds, so the label now says so (K). PYTHONHASHSEED=0 means "randomisation off", still a valid, different order.
- **Step 9.** Holds on the gate's platform. Overclaims fixed (E). Tamper refusal re-executed on both pips.
- **Lab.** Step 8's `pytest>=9` breakage didn't break on current pip; replaced (A). Step 7 (no-break space) also holds with awk in `C.UTF-8`.
