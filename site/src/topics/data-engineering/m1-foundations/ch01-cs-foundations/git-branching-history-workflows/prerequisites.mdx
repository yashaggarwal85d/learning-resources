### <span class="n">01</span> Everyday Git: commits, branches and a remote

Making a commit, creating and switching branches, and sharing work with <code>git push</code> and <code>git pull</code> against a remote such as GitHub. If you have only ever used Git through an editor's buttons, the two Pro Git chapters below take an afternoon and cover every command the reel assumes.

<p class="check"><b>Check yourself:</b> what does <code>git switch -c fix</code> do? (Answer: it creates a branch called <code>fix</code> at the current commit and switches to it.)</p>

### <span class="n">02</span> Reading a commit history

Every step of the reel is a picture of the commit graph: dots for commits, lines to their parents. You should be comfortable reading <code>git log --oneline --graph</code> and knowing that each commit points back at its parent, or at two parents for a merge.

<p class="check"><b>Check yourself:</b> in a history drawn as a graph, how do you recognise a merge commit? (Answer: it is the one commit with two parents, so two lines join into it.)</p>

### <span class="n">03</span> A script that fails with a test

The bisect steps use a tiny Python test: an <code>assert</code> that fails when the code is wrong, which makes the script stop with a non-zero exit code. Functions are covered by the Python refresher; <code>assert</code> is not: <code>assert condition</code> is shorthand for <code>if not condition: raise AssertionError</code>, and an uncaught exception ends the script with a non-zero exit status. The reading below is all you need for it.

<p class="check"><b>Check yourself:</b> what happens when an <code>assert</code> fails in a script? (Answer: it raises <code>AssertionError</code> and the script exits with a non-zero status, so a shell or a tool like <code>git bisect run</code> sees a failure.)</p>
