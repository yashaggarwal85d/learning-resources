### <span class="n">00</span> The terms this topic uses

A few words, each defined in full inside the reel; this is just so they are not a surprise.

- **Point-in-time / as-of join** — matching each row to the latest row of another table whose own timestamp is at or before the first row's timestamp.
- **`ASOF JOIN`** — native syntax (DuckDB, Snowflake, ClickHouse) for exactly this pattern.
- **Temporal leakage** — a training-data bug where a feature is joined to a "current" value instead of the value genuinely knowable at the training example's own time.
- **Bitemporal** — tracking two independent time axes (when something became true, and when the system learned about it), a strictly harder problem than the single-timestamp as-of join here.

<p class="check"><b>Check yourself:</b> can "join each order to the price in effect at order time" be written as a plain equality join on product_id alone? (Answer: no — equality alone would match every historical price for that product; the as-of behavior needs an added inequality (at or before the order's timestamp) plus "keep only the closest one.")</p>
