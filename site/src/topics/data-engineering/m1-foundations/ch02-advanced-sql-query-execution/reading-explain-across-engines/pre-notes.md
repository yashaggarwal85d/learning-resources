- **Cardinality estimation**: the planner's own guess, made before a query runs, at how many rows a given operator will produce. *Where you meet it:* the "estimated" half of this topic's own estimated-vs-actual comparison, on every engine covered.
- **Work_mem spill**: an operator running out of the memory it was given, and writing intermediate data to disk instead (introduced in topic 23). *Where you meet it:* this topic's own Spark spill measurement, and every other engine's own name for the same signal.
- **Adaptive query execution**: an engine revising its own plan once a stage's real output size is known (introduced in topic 26). *Where you meet it:* why Spark's cost-plan estimate and its UI's actual numbers can genuinely differ, not just appear to.
- **Loops**: how many times a plan node actually ran, when it sits beneath a nested loop or a repeated subplan. *Where you meet it:* this topic's own estimated-vs-actual reveal, where a high loop count multiplying a small per-call cost matters as much as a raw row-count gap.
