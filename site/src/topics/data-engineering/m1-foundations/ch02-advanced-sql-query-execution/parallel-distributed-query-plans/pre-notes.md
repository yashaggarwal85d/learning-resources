- **Partition-wise join**: PostgreSQL's planner joining matching partitions of two partitioned tables independently, instead of combining everything into one plan first. *Where you meet it:* this topic's own `enable_partitionwise_join`, measured both as a plan-shape change and a real memory/speed difference.
- **Exchange operator**: an explicit step in a distributed engine's plan that moves data between machines before the next operator can run. *Where you meet it:* Trino's own `RemoteExchange` plan nodes.
- **Shuffle (repartition)**: an exchange that hash-redistributes both sides of a join by the join key, so matching rows end up on the same node. *Where you meet it:* the step explaining how a shuffle manufactures, across a network, the same alignment a single machine's matching partitions already have.
- **Broadcast**: an exchange that copies one (small) side of a join whole to every node, instead of redistributing both sides. *Where you meet it:* Spark's own default broadcast threshold, 10 MB.
- **Co-located join**: a join where both tables are already partitioned the same way across the same nodes, so no exchange is needed before it can run. *Where you meet it:* the step connecting this directly back to this topic's own partition-wise join measurement, one level up.
