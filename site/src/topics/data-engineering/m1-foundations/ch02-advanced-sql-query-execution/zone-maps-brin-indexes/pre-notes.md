- **Composite index design and column order**: how a B-tree's own column order decides how much of it gets scanned (introduced in topic 28). *Where you meet it:* the contrast for this topic's much smaller, coarser kind of index.
- **Covering, partial and expression indexes**: refinements that each change what an index needs to visit or store (introduced in topic 29). *Where you meet it:* a block-range summary is a different kind of tradeoff again — not smaller by refining a B-tree, but by replacing per-row precision with per-range approximation.
- **EXPLAIN (ANALYZE, BUFFERS)**: the tool this chapter has used throughout to see a plan's real buffers and timing. *Where you meet it:* every measurement in this topic, including the one case where an index turns out not to help at all.
- **Bitmap index scan**: the scan type that returns a set of candidate pages instead of individual rows directly (seen in topic 27's cross-engine EXPLAIN work). *Where you meet it:* this is exactly how a block-range index's own matches reach the table — as a set of pages to recheck, not as rows already proven correct.
