- **Covering, partial and expression indexes**: refinements that let an index answer a query without visiting its own table, or shrink to a hot subset, or match a written expression exactly (introduced in topic 29). *Where you meet it:* this topic splits the table itself instead of refining one index over it.
- **Composite index column order**: how a multicolumn index's column order decides how much of it gets scanned (introduced in topic 28). *Where you meet it:* choosing a partition key is the same kind of decision, one level up — which predicates and which retention needs the key should serve.
- **EXPLAIN (ANALYZE, BUFFERS)**: the tool this chapter has used throughout to see a plan's real buffers and timing, not just its estimate. *Where you meet it:* every measurement in this topic — plan-time pruning, run-time pruning, and the planning-time overhead of many partitions.
- **VACUUM**: PostgreSQL's own maintenance command, already met as the fix for a stale visibility map (topic 29). *Where you meet it:* this topic's own measurement of the overhead a bulk DELETE still carries, which DROP TABLE on a partition avoids entirely.
