- **EXPLAIN (ANALYZE, BUFFERS)** and the sandbox's own measurement habit, used throughout this chapter. *Where you meet it:* this topic switches from measuring a single query's plan to measuring the cost of keeping a stored result current over time.
- **Block-range summary pruning** (introduced in topic 31). *Where you meet it:* a materialized view is a different kind of shortcut again — not a smaller structure to search, but a stored answer that needs its own maintenance.
- **Triggers**: a database's own mechanism for running code automatically on a row-level change (`AFTER INSERT`, `AFTER UPDATE`). *Where you meet it:* this topic's own incremental-maintenance measurement uses a trigger as an honest stand-in for the kind of incremental view maintenance PostgreSQL doesn't build in natively.
- **UNIQUE index**: an index that enforces no two rows share a value (seen throughout this chapter's earlier index topics). *Where you meet it:* `REFRESH MATERIALIZED VIEW CONCURRENTLY`'s own hard requirement.
