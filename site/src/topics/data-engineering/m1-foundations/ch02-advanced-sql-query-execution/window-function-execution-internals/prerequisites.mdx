### <span class="n">00</span> The terms this topic uses

A few words, each defined in full inside the reel; this is just so they are not a surprise.

- **Cumulative aggregation** — reusing the previous row's aggregate and adding only new rows, valid as long as the frame only grows.
- **Removable cumulative aggregation** — the same idea, extended to also subtract rows leaving the frame, for a sliding window.
- **Segment tree (here)** — a precomputed structure over sub-ranges of a partition that answers "aggregate over any range" in logarithmic time, used when frame bounds move unpredictably.
- **Inter-/intra-partition parallelism** — splitting work across whole partitions vs. splitting one oversized partition's own work across several threads.

<p class="check"><b>Check yourself:</b> does PostgreSQL's cumulative-aggregation algorithm handle a sliding frame like ROWS BETWEEN 5 PRECEDING AND 5 FOLLOWING as cheaply as the default growing frame? (Answer: no — cumulative aggregation only stays cheap while the frame grows; a frame that must also shrink needs the removable-cumulative extension or it degrades toward quadratic cost.)</p>
