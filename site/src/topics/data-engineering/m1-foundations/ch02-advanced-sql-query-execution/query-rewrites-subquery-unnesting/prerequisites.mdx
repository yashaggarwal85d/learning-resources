### <span class="n">00</span> The terms this topic uses

A few words, each defined in full inside the reel; this is just so they are not a surprise.

- **Join elimination** — deleting a join entirely when it's provably redundant (matches at most one row, and nothing from it is used).
- **Outer-join strength reduction** — converting a LEFT JOIN to a plain or anti-join once a later filter proves it behaves that way.
- **Dependent join** — Neumann & Kemper's formal name for a correlated subquery: a nested-loop-shaped join where the right side depends on the left row's values.
- **Unnesting (decorrelation)** — transforming a dependent join into an ordinary, reorderable join.

<p class="check"><b>Check yourself:</b> can a LEFT JOIN followed by `WHERE right_table.key IS NULL` ever be converted into the same plan as a NOT EXISTS anti-join? (Answer: yes — PostgreSQL's planner proves the LEFT JOIN only ever lets null-extended rows survive that filter and switches the join type to Anti directly, the same type NOT EXISTS compiles to.)</p>
