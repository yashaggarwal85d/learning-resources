### <span class="n">00</span> The terms this topic uses

A few words, each defined in full inside the reel; this is just so they are not a surprise.

- **Query tree** — PostgreSQL's name for the semantically-resolved, logical representation of a statement, built by the parser's "transformation process."
- **Path** — PostgreSQL's name for a candidate physical implementation of (part of) a plan; the planner compares many paths and keeps the cheapest.
- **Logical plan / physical plan** — what to compute (an algebra tree) vs. how (a specific algorithm and access method per operator).
- **Physical property** — a characteristic of a path's output, such as sort order, that a later operator may require or that an earlier one may already provide for free.

<p class="check"><b>Check yourself:</b> at the parse stage, does PostgreSQL already know whether a name in your query refers to a real table? (Answer: no — the parser only checks grammar and has no catalog access; resolving names to real tables/functions/operators happens in the next stage, the "transformation process.")</p>
