## Sandbox disclosure

No local Kubernetes cluster exists on this build machine: no reachable Docker daemon and no `kubectl`, `kind`, or `k3s`, the same limitation confirmed across every topic in this chapter. This topic has no lab of its own (the savepoint-preserving upgrade it builds toward is exercised end to end in the next topic's lab instead), so the main sandbox impact is that a live multi-broker Kafka roll and a live Flink Kubernetes Operator upgrade can't be run or measured here. Both are sourced from Strimzi's and Flink's own documentation and source files instead. What is run for real in `examples.py`: the ISR-safe rolling-restart decision (modeled directly on `KafkaAvailability`'s own logic, sixteen tests), the StatefulSet PVC-retention-policy resolution, and the Flink upgrade-mode and savepoint-fallback decisions (modeled directly on the operator's documented upgrade-mode table).
