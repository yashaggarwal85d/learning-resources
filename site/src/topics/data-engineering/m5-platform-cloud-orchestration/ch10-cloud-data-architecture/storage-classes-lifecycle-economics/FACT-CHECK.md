## Red team on the predict question (step 2)

Edge case tried: could a learner object that the lifecycle rule in the hook is simply misconfigured (wrong cutoff), not "blind" in any deeper sense? Checked against AWS's own lifecycle docs: a lifecycle rule's only inputs are an object's age, tags, prefix and size — there is no table-format-aware option at all, on any of the three clouds' lifecycle features. So the rule in the hook could have the perfect cutoff for every object that isn't part of a live table and still corrupt the one that is, because the rule has no way to ask "does anything still reference this file." The predict's answer explain text was worded around that distinction (a category of information the rule never has access to, not a tuning mistake) rather than implying a better cutoff would have fixed it.

## Outcome

No claim dropped. Object Lock (claim 4) is sourced-only by design (see OUTLINE.md's engine-of-record note) since it needs a real AWS account's IAM and retention enforcement to demonstrate directly; every sentence about it is quoted, not paraphrased, from AWS's own current documentation. All five `examples.py` reproductions ran and their asserted values are the ones shown on screen.
