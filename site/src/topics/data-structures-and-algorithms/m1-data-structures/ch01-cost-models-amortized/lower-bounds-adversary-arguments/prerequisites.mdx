<section class="prereq" data-section="asymptotics">

### <span class="n">01</span> Asymptotic notation, cases and averages

You can read Ω, Θ and O, you know what a worst-case bound claims, and you know the difference between an average over inputs and an expectation over an algorithm's coins. A lower bound is an Ω statement about a worst case or an average, so this is its language.

<p class="check"><b>Check yourself:</b> if every algorithm for a problem needs Ω(n log n) steps in the worst case, is it still possible that one algorithm is fast on a particular input? (Answer: yes; a worst-case bound says nothing about easy inputs.)</p>

### <span class="n">02</span> The word-RAM and the comparison model

You know what one step costs on the word-RAM, and that the comparison model counts only comparisons of keys. You know radix sort, van Emde Boas trees and fusion trees as the structures that leave the comparison model by using keys as numbers; this reel proves the bounds they escape.

<p class="check"><b>Check yourself:</b> why can radix sort beat n log n without contradicting any proof? (Answer: it reads the digits of a key, which no comparison does, so it is outside the model the proof is about.)</p>

### <span class="n">03</span> Recurrences, and merge sort's Θ(n log n)

You can read the cost of a divide-and-conquer algorithm off its recurrence. This reel meets that upper bound with a lower bound: merge sort's Θ(n log n), solved in the previous topic, is the answer the decision tree proves optimal.

<p class="check"><b>Check yourself:</b> what does T(n) = 2T(n/2) + n solve to, and which case of the Master theorem is it? (Answer: Θ(n log n); case 2, every level of the recursion tree costs n.)</p>

### <span class="n">04</span> Logarithms and n!

log₂ is the number of times you can halve a number, or the height of a binary tree with that many leaves. n! is the number of orders of n keys. The sorting bound is log₂ of n!, so you need to be comfortable with how large it is.

<p class="check"><b>Check yourself:</b> about how large is log₂(10!)? (Answer: about 21.8, so 22 comparisons are needed to sort 10 keys in the worst case. 10! = 3,628,800 lies between 2²¹ and 2²².)</p>

### <span class="n">05</span> Hash sets

A hash set answers “is this key present?” in O(1) time on average, with a randomly chosen hash function. You need to know that the promise is an expected one, not a worst case: the reel uses a hash set to decide distinctness and says what it gives up.

<p class="check"><b>Check yourself:</b> what does a hash set's O(1) lookup promise, the worst case or the expected case? (Answer: the expected case, over the choice of hash function; some inputs make any one fixed function collide.)</p>

### <span class="n">06</span> The standard sorts and binary search as procedures

You need to know what insertion sort, merge sort and binary search do, not their analysis: this reel draws insertion sort as a tree of comparisons and counts binary search's probes.

<p class="check"><b>Check yourself:</b> how many probes does binary search make on 1,000,000 sorted keys in the worst case? (Answer: 20, which is ⌊log₂ 1,000,000⌋ + 1.)</p>
