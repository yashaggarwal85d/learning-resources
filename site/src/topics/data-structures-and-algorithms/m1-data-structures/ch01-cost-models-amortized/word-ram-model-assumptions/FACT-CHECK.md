# Fact-check: The word-RAM model and its assumptions

Adversarial fact-check, currency check and red team of `OUTLINE.md` (ROUTINE.md section 2, step 3), done on 11 October 2026. Every claim was re-derived from the fetched texts in `sources/` (pdftotext output read as raw text, never a summary). All arithmetic and the toy data structures were recomputed in Python 3 in a scratch script (binary-search probe counts over 20,000 random queries, cache lines touched, log₂ n!, the fusion-tree words, and the sketch rank over all 256 8-bit queries). The corrections are applied in `OUTLINE.md`, each marked "(fact-check: …)". 29 quotes were added to `SOURCES.md` for them, and `node scripts/sources.mjs check` passes on all 153 quotes.

Sources opened: 6.851 lec11, lec12 and lec14 (Demaine, scribe notes); 6.006 Spring 2020 lec5; Agner Fog, *The microarchitecture of Intel, AMD and VIA CPUs* (last updated 2026-05-23); Drepper, *What Every Programmer Should Know About Memory* (2007); Pătraşcu–Thorup, arXiv cs/0603043v1 (2006); Fredman–Willard, JCSS 1993 (a course-hosted scan with OCR errors); Mehlhorn–Sanders, *The Basic Toolbox*, ch. 2 (the authors' PDF). No other source was opened, and no web request carried personal information.

## Red team: explanations and predict questions

1. **Step 3 (predict).** It asked for "fewer steps in the worst case, for any n". That is false for n < 64, where log₂ n < 6. It also counted 6 halvings against 20 comparisons as if both were single units. Reworded to "a worst-case query that does not grow with n". The answer frame now says halvings are "each a few word operations". The explanation cites Fredman–Willard that such structures win "only for sufficiently large values of N" and points to the space price. The wrong option "Only if the keys are small" is sharpened, because keys do have to fit in one word.
2. **Step 4.** "20 bits: an index up to 1,048,576" was off by one. 20 bits address 1,048,576 cells, from 0 to 1,048,575.
3. **Step 5 and Q3.** "How many unit steps, at least? 64" breaks, because the carry loop also does 128 loads and 64 stores, each a unit step. Q3 now asks for word additions. The multiply count names its two-word-product assumption.
4. **Step 7.** "A predictor has nothing to learn from" fails for repeated or sorted queries. The caption now says that for random queries each comparison is close to a coin flip.
5. **Step 10.** Moves and comparisons are different units, and n·log₂ n overstates the comparison floor by about 8%. The caption says "order" and names the units.
6. **Step 13.** The verdict conflated sketch order with key order. The toy's only query happened to land right, and a counter-example (q = 22) is now in the plan. The node word doesn't fit the toy's 8-bit "word".
7. **Q2.** "Lookup … cannot be beaten": if lookup means exact match, hashing (6.006: "expected O(1)") beats it on the word-RAM. That made the "hashing beats it" distractor arguably right. The quote now says predecessor. The distractor's explanation no longer claims hashing "gives up the worst case", which is unsourced here.
8. **Predecessor definition.** lec11 says "largest element of S less than some query x" (strict). Pătraşcu–Thorup use max{y ≤ x}, and Fredman–Willard say an unsuccessful search returns the predecessor. The plan now fixes ≤ and checks against `bisect_right`. Careful: with ≤, a query equal to a stored key must return that key. A naive sketch rank returns the key before it, which the desketchify assertion over all 256 queries covers.
9. **Q1, steps 11, 12 and 14.** These hold. The vEB bound depends on w only. Step 12's optimality statement already carried its "near-linear space" qualifier, and the Beame–Fich caveat was added for the Deep dive.
10. **Step 1 and step 8.** These hold: ⌈log₂(n + 1)⌉ = 20, and 9 → 5 → 3 → 2 → 1 with four answers.

## Currency

- Agner Fog's manual is the 2026-05-23 edition. Its latest AMD chapter is Zen 5, which is used. Its Zen 5 cache table (L1d 4 clocks, L2 14 clocks, 64-byte lines) was added as the current comparison point for Drepper's 2007 Pentium M figures. No opened source gives a current main-memory latency, so ~240 cycles stays labelled "Pentium M, 2007".
- Drepper (2007) and Mehlhorn–Sanders (2008) are dated, and `OUTLINE.md` labels them so.
- The 6.851 notes are from 2012 with 2017 scribes, and the integer-sorting "OPEN" is attributed to them.
- Nothing is renamed or superseded in the opened sources. lec11's model hierarchy calls it the "trandichotomous RAM" (a typo in the source).

## Remaining risks

- **lec11's operator list** loses a symbol in extraction, so the topic must not print lec11's list with "^" as a quote.
- **Andersson–Miltersen–Thorup 1999** is cited by title only, from lec12's reference list. Its paper was not opened, so the topic says only that an AC⁰ version exists and nothing about how it works.
- **Fredman–Willard** is an OCR scan. Several quotes keep OCR spellings ("multipliction", "sufticiently", "AC’"), and the randomized bounds ("O(m)", "O(Nm)") and the Paul–Simon operand factor ("N*") are unreadable. They must not be quoted as numbers.
- **Main-memory latency on current hardware** has no opened source. If the builder wants a 2026 number, it must open one (for example a vendor optimization guide) or keep the 2007 figure, labelled.
- **Cache-line size** is 64 bytes on the cores in the opened sources. Some non-x86 cores use other sizes, but no opened source covers them, so the topic should not claim 64 bytes is universal.
- **Who coined "transdichotomous"** remains unattributed, by design.
- The **"In production"** use of Pătraşcu–Thorup's 2006 remark on IP look-up ("The fastest deployed software solutions use non-comparison-based RAM tricks") must be dated and attributed, not presented as a current fact.
- **IPS⁴o/IPS²Ra (arXiv 2009.13569)** was not opened, so no claim is made that integer sorts are fast in practice.
