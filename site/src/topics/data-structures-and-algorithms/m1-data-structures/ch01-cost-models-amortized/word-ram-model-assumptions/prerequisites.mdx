<section class="prereq" data-section="asymptotics">

### <span class="n">01</span> Asymptotic notation and logarithms

You read O(·), Ω(·) and Θ(·) as bounds on how a cost grows, and you know that log₂ n is the number of times you can halve n. Every count in this reel is written in that language, and the reel opens by asking what machine those counts assume.

<p class="check"><b>Check yourself:</b> roughly how many times can you halve 1,000,000 before you reach 1? (Answer: about 20, since 2²⁰ = 1,048,576.)</p>

### <span class="n">02</span> Binary numbers, bits and bitwise operations

You know that a w-bit word holds a number from 0 to 2ʷ − 1, that a shift right by k bits divides by 2ᵏ (rounding down), and that & keeps only the bits set in both operands. The reel cuts a 64-bit key into halves and digits, so reading a number as a row of bits should feel natural.

<p class="check"><b>Check yourself:</b> what are 13 &gt;&gt; 2 and 13 &amp; 6? (Answers: 3, since 13 is 1101 in binary and shifting drops the last two bits; and 4, since 1101 &amp; 0110 = 0100.)</p>

### <span class="n">03</span> Binary search on a sorted array

You can describe how binary search finds a key (or the largest key at most x) in a sorted array by probing the middle and discarding half of the range, and why that takes about log₂ n probes.

<p class="check"><b>Check yourself:</b> how many probes does binary search need, at most, for 1,000 sorted keys? (Answer: 10, since 2¹⁰ = 1,024 ≥ 1,000.)</p>

<section class="prereq" data-section="sorts">

### <span class="n">04</span> The standard comparison sorts

The reel compares them with radix sort, so you need only know that merge sort and quicksort order keys by comparing pairs of them. Their analysis is not needed here; the lower bound on comparison sorting comes in a later topic of this chapter.

<p class="check"><b>Check yourself:</b> what does merge sort do after sorting the two halves of a list? (Answer: merges them into one sorted list by repeatedly taking the smaller front element.)</p>
