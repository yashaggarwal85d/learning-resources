## Red team: breaking the explanations and the predict questions

- **Step 4 predict (write-cursor bug).** Tried the "wrong" option in `examples.py` directly: replacing `cursor = list(offsets)` with `cursor = offsets` (no copy) reuses the same list object, and the second pass's `cursor[i] += 1` then corrupts `offsets` itself (confirmed: after one such run, `offsets[1]` reads 1 higher than it should, because the two names point at the same list). This makes the predict question's "correct" option a real, reproducible bug, not a hypothetical one — kept as is.
- **Step 6/7 predict (CSC).** Tried the distractor "scan all of targets for F's index" by hand: `targets` has no index organized by destination at all, so finding every source pointing at F this way means scanning the *entire* targets array, O(E) — not O(1) and not even O(in-degree(F)). The explain text already says this is wrong for the right reason (CSR isn't built to answer this) rather than just asserting CSC is needed; kept as is.
- **Step 10 predict (cache line).** Tried the distractor "only the single highest-degree hub benefits." Checked against the actual mechanism: every one of the 2,000 hubs benefits roughly equally, since the benefit is from any hub's read also prefetching ~7 *other* hubs' values in the same line — not something exclusive to the single top hub. Confirmed this distractor is wrong for the stated reason.
- **Edge case: what if a "hub" is also a non-hub's own direct neighbour, and gets read by a cold, uncached path too?** True, and not hidden: the measurement counts distinct cache lines the hub *entries* occupy, not every access pattern that could ever touch them. The post-notes' "frontier" section already flags that heavier-weight orderings (GOrder, RabbitOrder) target exactly this more complete picture, which degree sort's simpler signal does not fully capture — this topic does not overclaim that degree sort is the best possible ordering, only that it is a measurable, real one.
- **Scope check against the chapter's own named target (100M edges).** This topic's own measurement runs at 2,000,000 vertices (~16,000,000 edges), not 100,000,000. OUTLINE.md's "Lab" post-notes heading already states this explicitly as the sandbox-bound scale actually run, read against the syllabus's own larger target — not silently presented as if it were the full scale.

## Corrections applied to OUTLINE.md

- Step 11's narration and the post-notes "Lab" section: the published 4x/2x figures are now stated as resulting from degree sort *combined with* CSR segmenting, not degree-sort reordering in isolation (claim 5's correction above).
