## Red team

- **MatrixPredict (step 3).** Stress-tested all three wrong options against the actual mechanism, not just the right one: (a) fails because a cell is a single scalar, so it cannot hold two distinct weights no matter how the graph is read; (c) ("the matrix can only represent one edge between any pair, full stop") is a tempting overgeneralization — it is actually *false* for an **unweighted** multigraph, where a count faithfully represents "two edges exist"; the real limit is specifically about two parallel edges each keeping their own *distinct weight*. (d) ("depends on whether the graph is directed") tests whether a learner confuses direction with multiplicity: the chapter's own multi-edge is two edges on the *identical ordered pair* (same direction), so whether the overall graph is directed or undirected never changes that one cell is still shared. All three distractors hold up as genuinely tempting but wrong, not strawmen.
- **DAGReveal (step 6).** The original draft hedged with "(or a trimmed, cycle-free view of it)", implying the chapter's own canonical graph might contain a cycle that step 6 would have to work around. Red-teaming this: a two-edge multi-edge between one ordered pair does not by itself create a cycle (a cycle needs a return path), so there is no actual tension between "the graph has a multi-edge" and "the graph is acyclic" — the hedge was unnecessary caution, not a real constraint. **Correction applied:** the chapter's own small graph is built to be acyclic by construction (a true DAG), and the hedge is removed from `OUTLINE.md` step 6 and from the examples-to-execute list.
- **"Which representation each later algorithm assumes" (step 7).** This is a synthesis/framing claim (a real trade-off), not a single quoted fact, so it has no one source to re-derive; red-teamed instead for overclaiming. Checked that it names a genuine example in each direction (BFS/DFS → list; specific-pair-membership algorithms → matrix) rather than asserting one representation is "the" right one, which the claims-not-made section already states explicitly.

## Corrections applied to `OUTLINE.md`

- Step 6 ("DAGReveal"): removed the "(or a trimmed, cycle-free view of it)" hedge from the visual description; the chapter's own small graph will be constructed acyclic from the start (recorded as a build requirement, not a late patch).
- Examples-to-execute item 6: updated to verify the chapter's own actual graph directly (dropping the "or the cycle-free view used for step 6" alternative).

No claim required dropping or a source swap; every claim in the list was derived precisely from the quoted text, and the one real finding (the unnecessary hedge) was a planning-precision issue, not a factual error.
