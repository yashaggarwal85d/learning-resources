Written 2026-10-22 as the adversarial fact-checker and red team (self-review; no independent reviewer ran). Each claim from `OUTLINE.md` → "Claims list" is re-derived from the fetched source text in `sources/`, not from memory.

## Currency

Every source above was fetched 2026-10-22: the current C++20 working draft mirror (N4868; the actual ISO C++ standard's text does not materially differ on these clauses across recent editions, but this topic cites N4868 specifically and says so), the `main` branch of Folly and of CPython (both living repositories; the quoted lines are stable long-standing code/doc, not a recent change), and the current stable Rust `std` documentation. No claim depends on a version-specific detail that is likely to have changed since.

## Red team: predict questions

- **Step 2** ("Does the old memory ever come back?"): tried the counter-argument "an allocator could coalesce freed blocks regardless of the vector's own growth factor." True in principle, but the chapter's claim is specifically about the vector's *own* discarded chunks being reusable *by the same growth pattern's arithmetic*, which is exactly what Folly's source argues and what the reel says ("the vector's own discarded memory") — not a claim about allocator coalescing in general, which the Deep dive notes as a separate, real complication (jemalloc cooperation).
- **Step 6** ("What does Rust actually guarantee?"): tried reading Rust's silence as "might not even be amortized O(1)". The quoted sentence rules this out directly ("will of course guarantee O(1) amortized push"), so the wrong option "nothing at all" is clearly wrong once the full quote is shown, not merely tempting.
- **Step 9** ("Is a pointer safe after shrink_to_fit?"): tried the edge case of a vector already at `capacity() == size()` before the call — then shrink_to_fit has nothing to do and by the standard's own effects clause cannot reallocate, so "always invalid" is simply false in that case, strengthening rather than weakening the correct answer ("only if that branch reallocated").
- **Step 5** ("Four libraries, four growth policies"): checked that none of the four claims overstate version-independence. The reel's narration (per the lexicon rule) names GCC's library, Folly's fbvector, CPython, and Rust's Vec without claiming any of the three fixed-factor policies is mandated by a language standard — only `reserve`/`shrink_to_fit`'s behaviour (step 7–10) is a standard requirement; the growth factor itself is always an implementation choice, which step 5's caption says explicitly.

## Open items

None. Claim 4's limitation is recorded above and reflected in the reel's wording (attributed to Folly's account, not to GCC's source directly), so it is not an open gap, it is an accurately scoped claim.
