## The chapter

### The problem it solves

Every algorithm in Milestone 2 so far came with a polynomial bound and an invariant that made it obvious. Some questions have neither: place eight queens so none attack, fill a Sudoku, pick the subset of a configuration that satisfies every rule, order a set of tasks so every constraint holds. The answer is one of an astronomically large number of candidates, and nothing known walks straight to it. The obvious program generates every candidate and tests it: for eight queens that is C(64, 8) = 4,426,165,368 placements, of which 92 are solutions. **Backtracking** builds the candidate one decision at a time and abandons the partial candidate the instant it can no longer be completed, so a whole subtree of billions of candidates is discarded by one failed check. The same program with a smarter rule for which decision to make next, or with deductions that shrink every later decision, turns a search that does not finish into one that finishes in a hundredth of a second. This chapter's single reel teaches the technique and its one real lesson: **the tree is the algorithm, and what decides its size is where you prune and which variable you branch on, not the code that walks it.**

Chapter 23 is a "Backtracking, Search and SAT" chapter in the syllabus, but §23.1's three other topics (exact cover with Dancing Links, meet in the middle, branch and bound) and all of §23.2 (DPLL and CDCL SAT solvers) are *(skipped)*, so this chapter is one topic. Its post-notes are where those four are named, each once, as what the same tree becomes when it is made smarter.

### Order of ideas, and why

1. **§23.1 Backtracking with pruning (80).** One topic, built in the order the syllabus line names it, which is also the order of increasing cleverness: (a) the *enumeration* trees for subsets, permutations and combinations, which fix the choose–explore–undo template and the three tree sizes (2ⁿ, n!, C(n, k)); (b) N-queens, the first problem where a partial candidate can be *refuted*, so pruning appears and the node count falls from billions to thousands; (c) Sudoku, where checking a placement is not enough and each placement should also *deduce* (constraint propagation), shrinking every later choice; (d) the choice of *which* variable to branch on (minimum remaining values) and how the same solver is seconds on most puzzles and minutes on a rare one (heavy-tailed running time). Each stage changes only one thing about the same recursion, which is why they live in one reel.

### Shared notation and terms

- **Partial assignment / state:** the decisions made so far (queens placed in rows 0…i − 1; digits written so far). **Node** = a state; **depth** = decisions made; **branching** = the options at a node; **leaf** = a complete assignment or a dead end. The **search tree** (id `state-space-tree`) is the tree of all states a search visits.
- **Choose, explore, undo:** the three lines every backtracking function contains; the undo restores exactly what the choose changed, which is the invariant the whole topic rests on. A *copy-on-branch* variant (Norvig copies the candidate sets for each branch) is named as the alternative and the reason to prefer one over the other is stated.
- **Pruning:** abandoning a node because no completion of it can be a solution. A node is pruned **only** by a check that is *sound* (never discards a real solution); the topic states this and shows a non-sound prune as the one bug that silently loses answers.
- **Constraint propagation:** deducing, after each choice, what other squares can no longer be, until nothing more follows or a square has no candidate left (a contradiction, which prunes). Written with Norvig's two rules: a square with one candidate removes it from its peers; a unit with one place left for a digit puts it there.
- **Minimum remaining values (MRV):** branch on the variable with the fewest remaining candidates. The builder checks whether Haralick and Elliott (1980) name this principle "fail first" and says so only if the paper (or a source quoting it) does; the topic uses the name MRV, which Norvig uses, and nothing else.
- **Squares and units for Sudoku** are written as Norvig writes them (rows A–I, columns 1–9, `A1`…`I9`), so a reader of his essay recognises them.
- **Spoken numbers:** narration has no digits, symbols or code names (automatic check). Say "choose, explore, undo", "constraint propagation", "minimum remaining values", "peer", "unit", "branching factor"; speak every number in words; "N-queens" is said "N queens", "Sudoku" as itself (QUALITY.md #29).

### One visual language for the chapter's reel

The chapter builds from `site/src/reels/kit.tsx` and `DESIGN.md`'s briefing theme: black and white carry everything, colour is rare and means something. On top of that this chapter shares one grammar:

- **Colour:** `crema` a decision already made (a queen placed, a digit written, an edge to a visited node); `latte` secondary labels (depth, node count, a candidate set); `taupe` the part of the tree or board not yet visited; `caramel` **the thing to look at**: the node being expanded and the path from the root to it; `cinnamon` (rare) **the alternative being compared**: always the same side of each pair, the smarter search (MRV, or with propagation) against the plainer one; `cherry` with `cherryText` **the bad outcome**: a dead end (a queen with no safe column, a square with no candidate), drawn at the moment the branch is abandoned, and the one run in the heavy tail.
- **The tree is drawn as a tree, growing:** nodes appear as the search reaches them, in visiting order, one per beat, never as a finished diagram. A pruned subtree is drawn as a `taupe` stub with its **size printed on it** (the number of placements it contained), so "one failed check removed 2,401 candidates" is a number on the picture. A backtrack is the highlighted path walking *up* one edge (`Draw`), the undo made visible.
- **A board is drawn as what it is:** an 8 × 8 grid with queens as filled marks, the attacked squares of the newest queen shaded in `taupe`; a Sudoku as its 9 × 9 grid with the candidate set printed small in each uncertain square, so a propagation is seen as digits *disappearing* from several squares at once.
- **A count is the argument:** each stage ends with one big number counting up to its real value (placements examined: 4,426,165,368 against 2,057), shown as a `Count` beside the tree, never as a claimed ratio without the two counts behind it.
- **Reel shape.** One full topic (about 14–16 minutes, 3–4 predict questions, the first within the first four steps): open on the 4,426,165,368-against-92 problem, predict how many nodes the pruned search visits, the choose–explore–undo template on subsets and permutations, the N-queens tree with its pruned stubs, then the Sudoku grid and propagation, MRV against first-empty, the heavy tail, "Prove it".

### 80. Backtracking with pruning (`dsa.backtracking-pruning`): full, §23.1

- **Folder:** `backtracking-pruning`. About 15 min.
- **Scope (syllabus clause → what it delivers):**
  - "subsets, permutations and combinations": the **enumeration** form of backtracking: one recursive function with choose, explore, undo, drawn as a tree for each of the three problems on the chapter's four-element set (every subset: at each element, in or out, 2ⁿ leaves; every permutation: at each position, any unused element, n! leaves; every k-combination: increasing indices only, so no combination appears twice, C(n, k) leaves). The three tree sizes are stated and counted by the program, not asserted. Duplicates in the input (the multiset case) are handled by skipping an element equal to the previous sibling at the same depth, shown on a three-element input with a repeated value, because it is the standard place a first backtracking program silently double-counts. Output order is the tree's depth-first order, said once (lexicographic when the input is sorted). This clause teaches the *template* and nothing about speed: the trees are full, nothing is pruned yet.
  - "N-queens": the first search with **pruning**. The candidate space shrinks in countable steps (the progression on Wikipedia's page: C(64, 8) = 4,426,165,368 placements of eight queens; 8⁸ = 16,777,216 once there is exactly one queen per row; 8! = 40,320 once the columns must also all differ), and then the search goes further than the permutation list by refusing a placement if it shares a column or a diagonal with an earlier queen; the three attack tests (column c, diagonal r + c, anti-diagonal r − c) as sets or boolean arrays so each test is O(1); the pruned tree drawn for n = 4 in full (17 nodes, two solutions) and counted for n = 8 (2,057 calls, 92 solutions, first solution after 114). The topic states why pruning is *safe* (a partial placement with an attacked pair cannot be extended into a solution, because later queens only add pairs) and shows what an unsafe prune looks like by cutting a branch on a heuristic ("the queen is too near an edge") and watching solutions vanish against the OEIS count. That the node count is not smooth in n (first-solution counts 114, 262, 10,053, 199,636, 411,609) is shown, with the one-sentence reason (where in the tree the first solution happens to sit). The 12 fundamental solutions and the symmetry argument are named in the post-notes, not taught. Bit-vector tracking of the three sets is named in the post-notes as the same search with the sets packed into machine words, pointing at Chapter 25.
  - "constraint propagation (Sudoku)": why a placement check is not enough when each choice constrains many others. The grid, units (27) and peers (20 per square), and the candidate-set representation. **Propagation** as two rules: eliminating a digit from a square that has been decided (naked single), and placing a digit where a unit has only one square left for it (hidden single), applied until nothing changes, with a contradiction (a square with no candidate, or a digit with no square) as an immediate prune. Shown on the chapter's hard grid: propagation alone decides only 3 of the 64 empty squares (20 squares are single-valued after the 17 givens are entered, 61 remain uncertain; reproduced at planning time with Norvig's two rules), the candidate sets shrink visibly, and the remaining search space is still 4.6 × 10³⁸ (the product of the 61 candidate-set sizes, recomputed at planning time as 462,838,344,192 followed by 15 zeros, matching Norvig's 4.62838344192 × 10³⁸). The point of the number is that propagation is powerful and still nowhere near enough. Then search *on top of* propagation: pick a square, try each candidate on a copy of the grid (copy-on-branch, versus an explicit undo log, both named and the trade-off stated), propagate, recurse. The topic does **not** teach further human strategies (naked pairs, X-wing) and says that no finite list of them is complete, which is why search is still needed.
  - "variable-ordering heuristics as the difference between seconds and years": the choice of *which* square (variable) to branch on, and in which order to try its digits. **Minimum remaining values:** branch on the square with the fewest candidates, because it has the highest chance of being right and the cheapest subtree if it is wrong, measured against "first empty square" on the same grid (the planning measurement: not finished after 3,000,000 placements against a solution in 481). The word "years" is earned only by a measured or *derived* statement: the builder reports the first order's behaviour as "had not finished after N placements in S seconds" and, if it extrapolates, shows the arithmetic (for example the product of candidate-set sizes, 4.6 × 10³⁸, divided by a stated rate) and labels it an upper-bound estimate, never a measured year. **Value ordering** is named (least-constraining value) and is not built. Then the part experts must know: even a good ordering has a **heavy-tailed** run time: on Norvig's million random puzzles the median stayed at 0.01 s while the maximum kept growing (1,439 s for the worst, one of the 0.2% with no solution); randomising the value order turned a 190 s puzzle into under 0.02 s in 27 of 30 runs. The topic shows the builder's own seeded distribution on a log axis and names **randomised restarts** as the standard remedy without building a restart policy (verified at planning time from the paper's abstract on Springer: "random restarts can effectively eliminate heavy-tailed behavior"; the builder quotes it from the fetched page).
  - Leaves to other topics (named, not built): exact cover and Dancing Links, meet in the middle, branch and bound, and DPLL/CDCL SAT solving (skipped; one sentence each in the post-notes); why searching is hard in the worst case (NP-completeness, Chapter 33); the dynamic-programming alternative when subproblems *repeat* (Chapter 22, named in the opening as the contrast); bit tricks for the queens' sets (Chapter 25); the lexicographically-smallest-order and heap versions of search (Chapter 17).
- **Outcomes:**
  - Write the choose–explore–undo skeleton, and say for subsets, permutations and combinations how many leaves its tree has and why.
  - Build N-queens with O(1) attack tests, explain why the prune is safe, and count nodes against the unpruned enumeration to show the gap.
  - Solve a Sudoku by propagation plus search, and explain what propagation removes that a placement check cannot.
  - Choose a branching variable by minimum remaining values, and explain from a measured distribution why a solver's median and maximum run times can differ by a factor of ten thousand.
