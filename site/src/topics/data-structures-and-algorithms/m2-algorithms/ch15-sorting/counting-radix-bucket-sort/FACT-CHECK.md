## Currency check

- The DuckDB 2021 post and the 2023 ICDE paper are both dated, published documents, fetched 2026-11-05; no claim is extended to DuckDB's present-day engine, which this topic does not open, per `CHAPTER.md`'s own instruction.
- The McIlroy, Bostic & McIlroy 1993 paper and the Sedgewick & Wayne booksite page are both fetched 2026-11-05; the booksite page's own "Last modified" date (26 August 2016) is noted, since it is a living page, not a fixed snapshot.
- Herf's "Radix Tricks" page is fetched 2026-11-05; its content (a published, widely cited technique write-up) is not expected to change in substance.

## Red team

1. **The McIlroy, Bostic & McIlroy 1993 PDF's extracted text is heavily OCR-damaged**, especially through its code listings, variable names and ligature-heavy words. This topic quotes only the handful of plain-prose sentences that survive extraction cleanly and implements the cycle-leader mechanism from the paper's own prose description, not its garbled code — the same handling this project used for the CAV 2015 PDF in topic 52.
2. **The IEEE 754-2019 standard itself is not opened** (paywalled). This topic instead cites a widely reproduced, independently documented statement of the exact bit-flip rule (Herf's page), corroborated by a second source read at research time (a Rust crate's own documentation using the identical rule in its own words), which is treated as sufficient corroboration for a technique, not a standards citation.
3. **CLRS 4th ed. chapter 8 (its bucket-sort expected-cost lemma) is not opened this session** — citation-only, per `CHAPTER.md`'s own "numbers to verify" framing. This topic's bucket-sort expected-cost claim is instead verified directly by simulation, not by the book's own proof.
4. **Graefe's 2006 survey and Knuth's TAOCP vol. 3 section 5.2.5 are named only**, per `CHAPTER.md`'s own instruction; no claim in this topic rests on either.
5. **This topic does not open the DuckDB documentation for the engine's present-day sort behavior.** Per `CHAPTER.md`'s own instruction, no claim about DuckDB's current implementation is made; the topic states only what the 2021 post and the 2023 paper, both dated, say.
6. **The crossover measurement (200,000 radix moves vs 718,346 comparisons) compares two different units of work** — a key move and a key comparison do not cost the same on real hardware — so this is suggestive of radix sort's asymptotic advantage, not a wall-clock benchmark; `CHAPTER.md`'s own compiled-helper requirement is reserved for the post-notes lab, not this in-reel measurement.
7. **No specific present-day system is claimed to ship American flag sort.** The 1993 paper recommends it for general use; this topic does not extend that recommendation to any named system's current behavior, since no such claim was verified at research time.
