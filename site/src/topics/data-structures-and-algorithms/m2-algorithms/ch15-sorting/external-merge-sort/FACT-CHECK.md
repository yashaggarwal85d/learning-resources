## Red team

1. **Vitter's own book PDF drops the "much greater than" symbol (M ≫ B) entirely during text extraction**, leaving "when M\nB [136, 220]" with nothing between them. Worked around by quoting only up to "on the average," before the dropped symbol, and stating the condition (M much greater than B) in this topic's own prose rather than inside the quote.
2. **Knuth, TAOCP vol. 3 section 5.4.1 (the "snowplow" name for replacement selection, and its own derivation of the 2M expected run length) is not opened this session**, per `CHAPTER.md`'s own "not opened" framing. This topic cites Vitter's own book for the 2M claim instead (an independently fetchable, open-access primary source making the identical claim), and names "snowplow" only as the common nickname, without attributing its own derivation to a source this topic opened.
3. **Aggarwal & Vitter's original 1988 CACM paper is not independently opened this session.** Its own sorting bound is cited only by reference to Chapter 1 topic 8's own treatment of the same bound (`io-sort-bound`), per `CHAPTER.md`'s own instruction to reuse rather than re-derive; Chapter 1 topic 8 itself names the paper in its own `references.md` but does not carry quote blocks to copy, so this topic's own citation of the bound is to the paper's bibliographic details only, not a verbatim quote.
4. **Graefe, "Implementing sorting in database systems" (2006), is named only**, per `CHAPTER.md`'s own instruction; no claim in this topic rests on it.
5. **This topic does not independently verify what any specific named engine (Spark, an LSM compactor) does with multi-way merges beyond the one-sentence pointers `CHAPTER.md` itself allows**, and defers the engine-side detail entirely to the Data Engineering reel `de.external-merge-sort-k`, which is live on this site and cited by name, not re-opened or re-quoted here.
6. **Sedgewick & Wayne's *Algorithms* §2.2 and the CLRS external-sorting problem are not opened this session**, per `CHAPTER.md`'s own "to verify" framing; no claim in this topic rests on either.
7. **The 2M-average claim is a statement about the mean of a random variable, not an exact number**; this topic's own simulation on its own seed rounds to exactly 2.0, matching CHAPTER.md's planning value, but a different seed would produce a slightly different average in the same neighborhood. No claim in this topic treats 2M as an exact, deterministic figure.
8. **The links check (`check-all.mjs --only links`) reports a pre-existing "title mismatch (check by hand)" for the PostgreSQL work_mem link** (`prerequisites.mdx` labels it "Resource Consumption (work_mem)" while the live page's own `<title>` is "PostgreSQL: Documentation: 18: 19.4. Resource Consumption"). This is a cosmetic label-vs-page-title difference, of the same kind already present on roughly a hundred other links across already-live topics in this site (confirmed by the same check run), and is not specific to this topic's own content or sourcing; the label itself is accurate and the quoted text in `SOURCES.md` is still verified word for word by `sources.mjs check`.

## Corrections applied

- `reel.tsx`'s replacement-selection step originally nested escaped double quotes inside its double-quoted title string (`Knuth's own \"snowplow\": ...`) to render `"snowplow"` on screen. The build's own coverage check reported this exact step as missing from `reel.tsx` even though the rendered text looked correct — the checker's own string handling does not survive a nested escaped quote inside a title the way it survives a plain apostrophe. Fixed by rewording to "Knuth's own snowplow technique" with no nested quotes at all, and propagating the identical wording change into `coverage.json`'s three matching `step` references.
- `coverage.json`'s fourth syllabus clause ("and the spill path of large sorts, joins and aggregations") did not cover the syllabus line's own trailing pointer ("→ *Data Engineering* §1.3, Ch.7."), so the build's coverage check reported the syllabus line as not fully mapped. Fixed by extending the clause text to include the full trailing pointer. The first attempt at this fix kept the syllabus's own markdown asterisks around "Data Engineering" and still failed, because the site's own syllabus parser (`syllabus.ts`'s `clean()`) strips all asterisks before building the scope string a coverage clause is matched against; fixed by removing the asterisks from the clause text to match the parsed, markdown-stripped scope string instead of the raw markdown source.
- Three takeaways (replacement selection's floor/ceiling, the I/O-cost takeaway, and the "same mechanism" takeaway) were 27, 37 and 37 words respectively, all over this project's 20-word takeaway limit. Shortened to 16, 18 and 20 words.
- `scenes.tsx`'s `ThresholdTable` visual originally rendered five adjacent cells with the identical label "passes: 1", wide enough that the rendered text ran into its neighbor's text on both desktop and phone, failing the reel smoke test. Fixed by shortening every cell's label to a single digit ("1" or "2") and widening the cell spacing slightly, relying on the step's own caption text for context instead of a repeated label.
