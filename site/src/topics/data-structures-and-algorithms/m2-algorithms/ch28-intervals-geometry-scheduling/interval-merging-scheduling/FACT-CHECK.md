## Red team

- **Tie-breaking edge case:** does the earliest-finish-first proof still hold when two jobs share a finish time? Re-derived: the exchange argument only needs *a* job with the smallest finish time, ties broken arbitrarily; sorting is stable either way, so the proof is unaffected. No correction needed, noted in post-notes internals.
- **Insertion cost:** could binary search alone make insertion O(log n)? Tested against the claim in OUTLINE: no — an array still has to shift the absorbed run and everything after it, so the shift is O(n) regardless of how the splice point is found; the topic states both costs separately rather than implying binary search alone is a speedup for insertion overall.
- **Min-heap room count vs. depth, off-by-one check:** re-derived on the ten-booking data by hand (see `examples.py`'s own assertion) that the third room opens exactly at the moment three bookings are simultaneously open, confirming the witness argument, not just a coincidence of this one data set.
- **Weighted sting margin:** re-derived that 29 beats 28 by exactly one unit of weight on this specific seeded data (not a dramatic gap), which is itself the stronger teaching point: even a one-unit difference is enough for a safe-looking greedy rule to be wrong.
- **Predict-question distractors:** "fewest conflicts" is tempting because it sounds like it directly targets the objective (avoid interval that blocks the most others); its own counter-example (3 kept vs. earliest-finish's 4 on the 8-interval set) is a different, smaller data set than the main ten bookings, confirmed as deliberate in CHAPTER.md, not a mistake to fix.

No claim was dropped outright; one claim (NP-completeness framing, #7) was corrected to what the primary source actually supports.
