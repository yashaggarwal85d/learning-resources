## The chapter

### The problem it solves

Chapter 17 answered questions about reachability and structure on a graph with no weights at all: every edge counted for exactly one step, so the fastest way to a vertex was simply the fewest edges to it. This chapter puts a cost on every edge and asks a harder question: not merely a path, but the *cheapest* one. The thread through all four topics is **relaxation** — repeatedly asking "does going through this edge improve my current best estimate to a vertex," and the four topics differ only in what order relaxation is allowed to happen in, and what that order costs or forbids. Dijkstra's algorithm fixes the order by always relaxing the closest unsettled vertex next, which only works when every edge is non-negative. Bellman–Ford drops that restriction by relaxing every edge, in any order, enough times to guarantee convergence — and the same mechanism that guarantees convergence on a legitimate graph is exactly what detects a negative cycle, where no shortest path can exist at all. Floyd–Warshall and Johnson's algorithm answer the all-pairs version, either by brute-force dynamic programming over intermediate vertices or by running a single-source algorithm from every vertex after a one-time reweighting trick that removes negative edges without changing any shortest path. DAG shortest and longest paths close the chapter by showing that on an acyclic graph, relaxing in topological order (topic 61's own output) needs no priority queue, no repeated passes, and no cycle check at all — the ordering itself is the whole algorithm.

### Order of ideas, and why

1. **Dijkstra's algorithm (63, full).** First, because it is the direct generalisation of Chapter 17's own breadth-first search — a priority queue instead of a plain FIFO queue, settling the closest vertex instead of the next one in arrival order — and because its own restriction (no negative weights) is the natural question every later topic in this chapter answers by relaxing it.
2. **Bellman–Ford and negative cycles (64, full).** Second, because it is introduced explicitly as what Dijkstra cannot do: handle a negative edge, and detect a negative cycle as a structural fact about the graph rather than a crash or a wrong answer. Relaxation itself, not any particular order of it, is shown to be the one idea both algorithms share.
3. **Floyd–Warshall and Johnson's algorithm (65, full).** Third, because it is the first all-pairs question in the chapter, and because Johnson's algorithm is explicitly built from the previous two topics (a single Bellman–Ford pass to reweight, then Dijkstra from every vertex) rather than a new primitive — proof that the all-pairs case does not need new machinery, only a composition of what already exists.
4. **DAG shortest and longest paths (66, full).** Last, because it is the chapter's own punchline: on a graph where topic 61's topological sort already applies, every earlier topic's machinery (priority queues, repeated relaxation passes, negative-cycle checks) turns out to be unnecessary, and the single cheapest algorithm in the entire chapter is also the one with the strongest precondition.
5. **Handoff to Chapter 19.** Topic 66 ends on a single-source and single-pair question fully answered for every kind of graph this chapter considers. The same weighted graph holds a different question about the whole network at once: not a route between two vertices, but the cheapest set of edges that keeps every vertex connected to every other. Minimum spanning trees, next — already built and live as `dsa.cut-property-kruskal-s` and `dsa.prim-s-algorithm`, whose own bridge quotes this chapter's closing handoff verbatim.

### Shared notation and terms

- **Weighted graph.** `G = (V, E, w)`, `w: E → ℝ` (or `ℝ≥0` where a topic requires non-negative weights); `n = |V|`, `m = |E|`. Every topic states up front whether negative weights are allowed.
- **Relaxation.** For an edge `(u, v)` with weight `w(u, v)`, relaxing it means: if `dist[u] + w(u, v) < dist[v]`, set `dist[v] := dist[u] + w(u, v)` (and record `u` as `v`'s predecessor). This single operation is the one mechanism every algorithm in this chapter is built from — stated once here, named by number only in each topic.
- **Settled vs. unsettled (Dijkstra only).** A vertex is settled once its `dist` value is known to be final; Dijkstra's own correctness proof is exactly the claim that non-negative weights guarantee this the moment a vertex is popped from the priority queue.
- **Spoken numbers:** narration has no digits, symbols or code names (automatic check); say "Dijkstra's algorithm", "Bellman-Ford", "Floyd-Warshall", "Johnson's algorithm", "relaxation", "negative cycle"; speak every number in words (QUALITY.md #29). "O of m plus n, log n" and similar complexity expressions are spoken as a description of the growth rate, not read as a formula.

### 63. Dijkstra's algorithm (`dsa.dijkstra-s-algorithm`): full

- **Folder:** `dijkstra-s-algorithm`. About 14 min.
- **Scope (syllabus clause → what it delivers):**
  - "label-setting with a priority queue": Dijkstra's own algorithm, settling the closest unsettled vertex on every iteration via a min-priority-queue keyed on current distance estimate, built and run on a small weighted graph with more than one path between some pair of vertices, confirming the settled distances match a brute-force shortest-path computation.
  - "why non-negative weights are required": a constructed counterexample graph with one negative edge where Dijkstra, run unmodified, settles a vertex with a wrong (too-large) distance before a later relaxation through the negative edge would have improved it — demonstrating the failure directly, not merely asserting the restriction.
  - "lazy deletion vs decrease-key": both variants of handling a vertex's distance improving after it is already in the queue — lazily pushing a new, smaller entry and skipping stale pops versus an actual decrease-key priority queue operation — built and compared on the same graph, with the one practical trade-off (lazy deletion is simpler and works with Python's/most languages' standard binary heap; decrease-key needs a heap that supports it, at the cost of more complex bookkeeping).
  - "O((m + n) log n) with a binary heap": stated and reasoned from the algorithm's own structure (each of the m edges can cause one push, each of the n vertices is popped once, each heap operation is O(log n)), not independently re-derived from first principles.
- **Outcomes:**
  - Run Dijkstra's algorithm on a weighted graph and confirm its settled distances match a brute-force shortest-path computation.
  - Construct a graph where a negative edge breaks Dijkstra's own guarantee, and explain why.
  - Compare lazy deletion against decrease-key on the same graph, and state the trade-off between them.
- **Introduces:** `dijkstra-algorithm`, `relaxation`, `label-setting`, `lazy-deletion`, `decrease-key`. **Uses:** `breadth-first-search` (topic 59, the unweighted special case this generalises), `binary-heap`/`priority-queue` (Chapter 6), `adjacency-list` (Chapter 10).
- **Bridge:** word for word, topic 62's handoff above ("Finding one key, one boundary, one order statistic... Dijkstra's algorithm, next.").
- **Handoff:** "Dijkstra's algorithm settles the closest vertex first, and that greedy choice is only safe because no edge can ever make a path shorter by being added to it. The moment even one edge weight can be negative, that safety breaks, and the closest-first order stops being trustworthy. Handling that case — and detecting when it makes the very question unanswerable — is next. Bellman-Ford and negative cycles, next."
- **Prerequisites panel:** topic 59 (Before this, contrast with the unweighted case); Chapter 6 "Binary heaps and heapify" (Before this, for the priority queue). On-site: topics 64–66 as "Goes deeper later".
- **Pre-notes terms:** weighted graph (recap from Chapter 10's own edge-list treatment), priority queue (recap from Chapter 6), shortest path (one line: the path whose edge weights sum to the least).
- **Hook:** a road network where every edge has a drive time, and the question is the fastest way from one city to every other — answered without ever reconsidering a city once its fastest time is known, as long as no road can ever make a trip shorter by being driven. Predict: if a graph has a single negative-weight edge somewhere in it, does Dijkstra's algorithm still find the correct shortest distances? (No: a vertex can be settled with a too-large distance before a later relaxation through the negative edge would have improved it.)
- **Visual idea:** a weighted graph with a live distance label under each vertex, updating as the priority queue pops the next-closest vertex (`caramel`) and relaxes its outgoing edges; a side panel showing the queue's own contents; a second, cherry-coloured pass on a graph with one negative edge, settling a vertex at the wrong distance before the negative edge is ever reached.
- **Sources to start from:** Dijkstra, "A note on two problems in connexion with graphs" (*Numerische Mathematik* 1, 269–271, 1959) — fetch and quote the original algorithm statement if available, else cite via a secondary source stated as such; CLRS 4th ed. or an equivalent course-notes source for the lazy-deletion vs. decrease-key contrast and the O((m + n) log n) bound's derivation.

### 64. Bellman–Ford and negative cycles (`dsa.bellman-ford-negative-cycles`): full

- **Folder:** `bellman-ford-negative-cycles`. About 14 min.
- **Scope (syllabus clause → what it delivers):**
  - "|V| − 1 relaxation rounds": the algorithm's own termination bound (any shortest path, if one exists, has at most |V| − 1 edges, so |V| − 1 full rounds of relaxing every edge are always enough) stated and demonstrated on a graph where the correct distances only stabilise on the final permitted round, not earlier.
  - "negative-cycle detection and extraction (currency arbitrage)": a |V|-th round that still finds an improving relaxation proves a negative cycle exists; the topic builds a small currency-exchange-rate graph (converting the arbitrage question — can trading through a cycle of currencies produce more money than you started with — into negative edge weights via a logarithm) where a profitable arbitrage loop appears as a negative cycle, detected and the actual cycle extracted by following predecessor pointers.
  - "the queue-based SPFA variant and its worst case": the Shortest Path Faster Algorithm (a FIFO-queue-driven variant that only re-relaxes a vertex's outgoing edges when that vertex's own distance has just improved, usually far fewer than |V| − 1 full rounds in practice) built and measured against plain Bellman–Ford on the same graph, with the one constructed adversarial graph where SPFA's own worst case degrades back to the same O(VE) bound as the naive version.
- **Outcomes:**
  - Run Bellman–Ford on a graph with a negative edge but no negative cycle, and confirm the distances stabilise within |V| − 1 rounds.
  - Detect a negative cycle from a currency-arbitrage-shaped graph and extract the actual cycle of edges that proves it.
  - Measure SPFA's relaxation count against plain Bellman–Ford's on both a favourable graph and an adversarial one built to hit SPFA's own worst case.
- **Introduces:** `bellman-ford-algorithm`, `relaxation-round`, `negative-cycle-detection`, `spfa`. **Uses:** `relaxation` (topic 63, the one shared mechanism), `queue` (Chapter 2), `edge-list` (Chapter 10).
- **Bridge:** word for word, topic 63's handoff above ("Dijkstra's algorithm settles the closest vertex first... Bellman-Ford and negative cycles, next.").
- **Handoff:** "Bellman-Ford answers the single-source question for any graph with a well-defined answer at all, negative edges included. The all-pairs version of the same question — every vertex's distance to every other, all at once — could run either algorithm from every single source in turn, but a graph with negative edges would need Bellman-Ford's own slower rounds run n separate times. There is a way to pay that cost only once. Floyd-Warshall and Johnson's algorithm, next."
- **Prerequisites panel:** topic 63 (Before this, the greedy guarantee this topic relaxes). On-site: topics 65–66 as "Goes deeper later".
- **Pre-notes terms:** relaxation (recap from topic 63, stated as the one shared mechanism), negative cycle (one line: a cycle whose total edge weight is negative, making a shortest path along it undefined).
- **Hook:** a loop of currency exchanges that, followed all the way around, leaves you with more money than you started with — a real possibility for a few seconds on a real exchange, and exactly what a negative cycle in a weighted graph means. Predict: if Bellman-Ford runs a |V|-th round of relaxation and no distance improves anywhere, does that prove the graph has no negative cycle? (Yes: a negative cycle would guarantee at least one more improving relaxation forever, so none improving on the |V|-th round rules it out completely.)
- **Visual idea:** a weighted graph with every edge relaxed each round, a round counter ticking up, distances visibly settling by the final round; a currency-exchange-rate graph with a `cherry` cycle highlighted the moment a |V|-th round still finds an improvement, predecessor pointers traced back around the cycle; a side-by-side relaxation-count comparison between plain Bellman-Ford and SPFA on the same graph, then on an adversarial one.
- **Sources to start from:** Bellman, "On a routing problem" (*Quarterly of Applied Mathematics* 16, 87–90, 1958) and/or Ford's original report — fetch and quote if available, else cite via a secondary source stated as such; a primary or well-regarded secondary source on SPFA (Duan, 1994, originally published in Chinese; an English-language secondary description, stated as such, if the original is not accessible) for the queue-based variant and its known worst case.

### 65. Floyd–Warshall and Johnson's algorithm (`dsa.floyd-warshall-johnson-s`): full

- **Folder:** `floyd-warshall-johnson-s`. About 15 min.
- **Scope (syllabus clause → what it delivers):**
  - "O(n³) DP over intermediate vertices": Floyd–Warshall's own recurrence (the shortest path from i to j using only the first k vertices as intermediates either avoids vertex k entirely, or passes through it once) built directly as a triple-nested loop over all pairs and every candidate intermediate vertex, run on a small graph with negative edges but no negative cycle and confirmed against a brute-force all-pairs computation.
  - "transitive closure, path reconstruction": the same DP, run with boolean reachability instead of weights, computing the transitive closure of a directed graph directly; path reconstruction via a predecessor matrix updated alongside the distance matrix, confirmed to reproduce an actual shortest path, not merely its length.
  - "Johnson's potential reweighting for all-pairs on sparse graphs with negative edges": Johnson's algorithm (a single Bellman-Ford pass from an added source vertex to compute a potential for every vertex, then reweighting every edge by that potential to remove all negative weights without changing any shortest path, then running topic 63's Dijkstra from every vertex) built and measured against Floyd–Warshall on the same graph, with the one practical trade-off (Johnson's O(n² log n + nm) beats Floyd–Warshall's O(n³) specifically when the graph is sparse, m much less than n²).
- **Outcomes:**
  - Compute all-pairs shortest distances with Floyd–Warshall on a graph with negative edges and no negative cycle, and confirm the result against a brute-force computation.
  - Reconstruct an actual shortest path (not just its length) from the predecessor matrix Floyd–Warshall builds alongside the distances.
  - Run Johnson's algorithm (reweighting plus Dijkstra from every vertex) on the same graph and confirm it matches Floyd–Warshall's distances exactly.
- **Introduces:** `floyd-warshall-algorithm`, `transitive-closure`, `path-reconstruction`, `johnson-s-algorithm`, `potential-reweighting`. **Uses:** `dijkstra-algorithm` (topic 63), `bellman-ford-algorithm` (topic 64), `dynamic-programming` (the intermediate-vertex recurrence, built here, not assumed from elsewhere), `adjacency-matrix` (Chapter 10).
- **Bridge:** word for word, topic 64's handoff above ("Bellman-Ford answers the single-source question... Floyd-Warshall and Johnson's algorithm, next.").
- **Handoff:** "Every algorithm so far has answered a question between two vertices, or from one vertex to every other. A directed graph with no cycle at all — a schedule, a build, a plan — makes the question easier than any of them needed to be: relax every edge exactly once, in the one order topic 61 already builds, and every shortest and longest path falls out for free, with no priority queue, no repeated rounds, and no cycle to ever worry about. DAG shortest and longest paths, next."
- **Prerequisites panel:** topics 63–64 (Before this, both algorithms Johnson's composes). On-site: topic 66 as "Goes deeper later".
- **Pre-notes terms:** all-pairs shortest paths (one line: every vertex's shortest distance to every other vertex, computed together), transitive closure (recap: which vertices can reach which, ignoring weights), dynamic programming (recap: building a solution from solutions to smaller subproblems).
- **Hook:** a network of a few hundred cities where every pair's fastest route is wanted at once, not one pair at a time — answered either by one dynamic program over every possible waypoint, or by running the single-source algorithm already built from every city, once a one-time trick removes every negative road. Predict: for a graph with a thousand vertices and only a few thousand edges (sparse), which approach does less total work: Floyd-Warshall's fixed O(n-cubed), or Johnson's algorithm running Dijkstra from every vertex? (Johnson's: its cost depends on the edge count, which is small here, while Floyd-Warshall's cost depends only on the vertex count and ignores how sparse the graph is.)
- **Visual idea:** an n-by-n distance matrix filling in one intermediate vertex at a time, a single cell lighting up `caramel` when a shorter path through the current intermediate is found; a predecessor matrix traced back to reconstruct one actual path; a reweighted copy of the same graph with every edge now non-negative, Dijkstra's priority queue running from each vertex in turn, final distances matching Floyd-Warshall's exactly.
- **Sources to start from:** Floyd, "Algorithm 97: Shortest path" (*Communications of the ACM* 5(6), 345, 1962) and Warshall's original transitive-closure algorithm (*Journal of the ACM* 9(1), 11–12, 1962) — fetch and quote if available, else cite via a secondary source stated as such; Johnson, "Efficient algorithms for shortest paths in sparse networks" (*Journal of the ACM* 24(1), 1–13, 1977) for the potential-reweighting algorithm, fetched and quoted if available.

### 66. DAG shortest and longest paths (`dsa.dag-shortest-longest-paths`): full

- **Folder:** `dag-shortest-longest-paths`. About 13 min.
- **Scope (syllabus clause → what it delivers):**
  - "relaxation in topological order in O(n + m)": on a directed acyclic graph, relaxing every outgoing edge of each vertex exactly once, in the topological order topic 61's own algorithms already produce, gives correct shortest distances in a single linear pass — no priority queue, no repeated rounds, and (since a DAG has no cycle by definition) no negative-cycle check is even meaningful — built and confirmed against Bellman-Ford's own (slower, more general) answer on the same graph.
  - "longest path and critical path in schedules": negating every edge weight before the identical single-pass algorithm turns the shortest-path computation into a longest-path one (correct specifically because the graph is acyclic — on a general graph, longest path is NP-hard, a fact stated but not proven here); the longest path from a schedule's start to its end is exactly its critical path, the topic's own worked example building a small task-dependency DAG and reading its critical path off directly.
- **Outcomes:**
  - Compute shortest distances on a DAG by relaxing edges in topological order, in a single linear pass, and confirm the result against Bellman-Ford's answer on the same graph.
  - Compute the longest path in the same DAG by negating edge weights, and explain why this trick is only valid because the graph is acyclic.
  - Build a small task-dependency DAG and read its critical path off as the longest path from start to end.
- **Introduces:** `dag-relaxation`, `dag-longest-path`, `critical-path`. **Uses:** `topological-sort` (topic 61, the ordering this entire topic is built from), `relaxation` (topic 63), `directed-acyclic-graph` (Chapter 10).
- **Bridge:** word for word, topic 65's handoff above ("Every algorithm so far has answered a question between two vertices... DAG shortest and longest paths, next.").
- **Handoff:** "Shortest and longest paths answered the question 'what is the cheapest way from this vertex to the rest'. The same weighted graph holds a different question, one about the whole network at once: not a route, but the cheapest set of links that leaves every vertex still connected. Cut property and Kruskal's algorithm, next."
- **Prerequisites panel:** topic 61 (Before this, the ordering this topic is built from); topics 63–65 (Before this, the general algorithms this topic's single pass outperforms on this one kind of graph). On-site: none later in this chapter.
- **Pre-notes terms:** critical path (one line: the longest chain of dependent tasks in a schedule, which sets the schedule's minimum possible length), topological order (recap from topic 61).
- **Hook:** a project schedule where some tasks can run in any order but others must wait on several others finishing first — and the single number that decides how fast the whole project can possibly finish is just the longest path through a DAG already built earlier this chapter, found by the cheapest algorithm in the entire chapter. Predict: does the single-pass, topological-order relaxation this topic builds work correctly on a graph that has even one cycle in it? (No: without a topological order to relax in, a vertex could be relaxed before one of its own predecessors has its final distance, giving a wrong answer with no warning.)
- **Visual idea:** topic 61's own topological-order visual, reused directly, with a distance label updating live under each vertex as edges are relaxed strictly left to right along the order; the identical pass re-run with every weight negated, producing the longest path instead; a small task-dependency DAG with its critical path highlighted `caramel` end to end.
- **Sources to start from:** CLRS 4th ed. or an equivalent course-notes source for the DAG shortest-path algorithm and its O(n + m) correctness proof; a critical-path-method (CPM) reference (Kelley & Walker, 1959, the original operations-research source, or a well-regarded secondary source stated as such) for the critical-path framing.
