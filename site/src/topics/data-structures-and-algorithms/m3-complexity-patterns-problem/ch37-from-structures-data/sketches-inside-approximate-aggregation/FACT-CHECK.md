## Red-team pass

- **Overclaiming "sketches merge" as one uniform guarantee.** HyperLogLog's merge is exact at the register level (claim 10); a quantile sketch's merge is only within a stated error. The outline and reel keep these two claims separate rather than folding them into one blanket "sketches merge" statement, since CHAPTER.md itself distinguishes "exactly for HyperLogLog's register maximum" from "within the error guarantee for quantile and top-k sketches."
- **The over-count claim (11) is about this topic's own synthetic data, not a law.** If customers never repeated across partitions (e.g., partitioned by customer id), the sum would not over-count. The claim as written is scoped to "whenever a customer appears in more than one partition," which is true by definition and is also what this topic's stream deliberately does — checked that the claim's wording does not imply this happens for every partitioning scheme.
- **The averaging-medians claim (12) needed a genuinely skewed example to be true in general**, not just on a lucky draw: a median over evenly-sized, similarly-distributed partitions would not show a large gap. The stream's eighth partition is deliberately both much smaller and drawn from a different, higher value range, matching CHAPTER.md's own hook example; re-ran with the random seed unchanged to confirm the gap is not a one-off artifact of a particular draw (the generation is already deterministic, so "re-running" means re-executing the same seeded script, which reproduced the identical numbers both times).
- **No claim about which engine uses t-digest or DDSketch internally.** CHAPTER.md explicitly forbids this ("no claim about t-digest or DDSketch usage in any named product is made from this plan — not opened"); this topic's sources list and FACT-CHECK table both omit any such claim, and post-notes.md's frontier section says so explicitly if the topic names t-digest at all.
- **Cassandra's/Redis's/Kafka's structures from topics 122/123 are not re-explained here**; this topic only reuses their concept ids (`fixed-slot-table`, `token-ring-partitioning`) as the partitioned stream's own placement scheme, matching the plan's instruction that this topic owns merging, not placement.
- **The Bloom-filter OR-merge (claim 13) is named once, briefly, as CHAPTER.md instructs** ("a Bloom filter is also mergeable by OR if built with equal parameters, said once") — checked that the reel gives it one step, not a full treatment duplicating Chapter 12 or topic 117.

Corrections applied: the quantile-sketch citation (claim 6) was first written as a single quoted sentence spanning the source's own two-line comment wrap; `sources.mjs check` rejected it because the wrapped line's leading `*` lands in the middle of the normalized text. Fixed by quoting only the first line, which is itself a complete, correctly attributed clause. No other claim required a change to its wording after the red-team pass.
