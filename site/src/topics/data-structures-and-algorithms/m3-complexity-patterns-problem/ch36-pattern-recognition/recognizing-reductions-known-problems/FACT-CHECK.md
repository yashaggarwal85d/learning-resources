## Red-team pass

- **Is the flow-versus-brute-force check on the reviewer instance strong enough, or could both methods share the same bug?** The two methods share no code: the flow algorithm follows augmenting paths through a residual graph, while the brute-force search enumerates subsets of a fixed edge list and checks capacity constraints directly, with no graph-traversal logic in common. Agreement between them is a meaningful check, not a coincidence of shared code.
- **Does the odd-cycle example actually demonstrate the near-miss, or does it just show a small graph that happens not to be bipartite?** Both: `is_bipartite` is run as a general, correct algorithm (two-colouring by breadth-first search) on the identical graph that also passes the bipartite test for the real matching instance, so it is not a special-cased check; and the brute-force matching-size search independently confirms the odd cycle's maximum matching is smaller than a perfect matching would require.
- **Is the two-SAT unsatisfiable instance a genuine test, or could any implementation bug "pass" by always returning unsatisfiable?** No — the identical implementation is also run on the satisfiable instance and correctly returns satisfiable there, so a bug that always returns one answer would have failed one of the two checks.
- **Is "a longest path in a graph with cycles is NP-hard" an overstatement?** The claim in the reel is phrased carefully as "the Hamiltonian-cycle family of problems," pointing at the already-sourced Erickson quote rather than asserting an independent proof of hardness for general longest path; this topic does not claim to prove that reduction itself, only to name the family correctly.
- **Is naming matrix traversal and binary search on the answer on the catalogue page, without a fresh code demonstration, a shortcut that undercounts the catalogue?** Documented explicitly in OUTLINE.md as a deliberate choice: both patterns already have a real, verified demonstration in topics 113 and 115 respectively, and rebuilding them here would duplicate rather than add verification.
